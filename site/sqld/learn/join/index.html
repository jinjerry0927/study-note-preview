조인JOIN Concepts

개념부터 차근차근!

두 표를 하나의 답으로 연결해 볼까요? 조인(JOIN)

06Q에서는 조회 결과의 순서를 정했어요. 이번에는 정보가 서로 다른 표에 나누어져 있을 때 어떤 열로 연결하고 왜 결과 행 수가 달라지는지 직접 살펴봅니다.

JOIN의 핵심은 조건과 결과 행 수입니다. INNER JOIN은 일치 행만 남기고, LEFT JOIN은 왼쪽의 미일치 행도 보존해요. CROSS JOIN은 모든 조합, 1:N 연결은 한 행을 여러 행으로 만들 수 있습니다. 결과 순서는 ORDER BY가 없으면 보장되지 않습니다.

이 단원을 끝내면

  1. 1분리된 테이블을 연결하는 이유와 올바른 결합 키를 설명해요.
  2. 2등호 조인과 시간 범위로 연결하는 비동등 조인의 결과를 구별해요.
  3. 3INNER JOIN에서 일치하는 행과 NULL 때문에 매칭되지 않는 행을 찾을 수 있어요.
  4. 4LEFT OUTER JOIN이 보존하는 행과 NULL 채움의 의미를 설명해요.
  5. 5CROSS JOIN의 결과 행 수를 곱셈으로 예측해요.
  6. 6세 테이블을 연결하는 두 개의 ON 조건을 추적해요.
  7. 71:N 조인과 COUNT(*)·COUNT(DISTINCT) 결과가 다른 이유를 설명해요.
학습 기록을 불러오는 중이에요.
01

01. 두 표에 나뉜 정보, 어떻게 함께 읽을까요?

학생 명단에는 학과 코드가 있고, 학과 명단에는 코드와 학과 이름이 있어요. 학생의 학과 이름을 알려면 두 표의 같은 학과 코드를 연결해야 합니다. 이것이 JOIN(조인)의 기본 목적이에요.

! 먼저 구분하세요

조인은 여러 표를 조건에 따라 결합한 결과 행을 만들어요. 표 자체를 영구적으로 합치거나, 외래키가 있다는 이유만으로 자동으로 조인하지 않습니다.

02

02. 무슨 값을 기준으로 두 표를 이을까요?

학생 표의 department_id와 학과 표의 department_id가 같으면 학생 옆에 학과 이름을 붙일 수 있습니다. SQL에서는 ON s.department_id = d.department_id처럼 어떤 열을 비교할지 명확히 적어요.

↳ 다른 테이블의 같은 이름 열

두 표 모두 department_id가 있으므로 s.department_id, d.department_id처럼 테이블 별칭과 점(.)으로 어느 열인지 구분해요. 반면 열 이름이 서로 달라도 값의 의미가 맞으면 조인할 수 있습니다.

! NULL은 등호로 일치하지 않습니다

S105의 department_id는 SQL NULL이에요. NULL = NULL도 TRUE가 아니라 UNKNOWN이므로 일반적인 ON a = b에서 매칭되지 않습니다. 연결 실패와 LEFT JOIN으로 행을 보존하는 일은 별개예요.

03

03. 같은 값만 연결할까요, 범위로도 연결할까요?

=로 연결하면 동등 조인(EQUI JOIN), <, >, <=, >= 같은 조건으로 연결하면 비동등 조인(NON-EQUI JOIN)이라고 해요. 예를 들어 학습시간 7시간은 7 ≤ 시간 < 9인 구간 B2와 연결할 수 있어요.

06R 실습용 시간 구간: 아래쪽 포함, 위쪽 제외

! BETWEEN은 양끝 모두 포함

구간이 0~7, 7~9, 9~12처럼 경계에서 만날 때 BETWEEN min_hours AND max_hours를 쓰면 7·9시간 학생이 중복 매칭됩니다. 이 예시에서는 >= min_hours AND < max_hours를 사용해 서로 겹치지 않게 했어요.

04

04. 조건이 맞는 행만 남기면 어떻게 될까요?

INNER JOIN은 조인 조건이 참인 행의 쌍만 반환해요. 학생과 학과를 합치면 학과가 없는 S105는 빠져서 5행이에요. 그러나 학생과 수강을 합치면 수강 기록이 7건이라 결과는 7행이에요.

↳ 결과 행 수를 결정하는 것은 관계

학생 1명과 학과 1개처럼 연결될 수도 있고, 학생 1명과 수강 기록 여러 개처럼 1:N으로 연결될 수도 있어요. JOIN이라고 결과가 항상 학생 수만큼 나오는 것은 아닙니다.

! WHERE로 조건 추가

INNER JOIN ... ON은 어떤 행을 연결할지 정하고, WHERE는 만들어진 행을 추가로 걸러요. 여기서는 표준 SQL 형태의 ON을 사용하지만 USING·NATURAL JOIN 비교는 다음 단원에서 자세히 배웁니다.

05

05. 연결되지 않은 행도 보고 싶다면?

LEFT OUTER JOIN(줄여 LEFT JOIN)은 왼쪽 표의 행을 모두 보존해요. 오른쪽에 일치하는 행이 없으면 오른쪽 열만 NULL로 채웁니다. 학생을 왼쪽에 두면 S105도 남아요.

↳ 보존되는 쪽은 표의 위치에 따라 바뀝니다

학생 LEFT JOIN 학과는 학생을 모두 남기고, 학과 LEFT JOIN 학생은 학과를 모두 남겨요. 소속 학생이 0명인 D30도 두 번째 쿼리에서 한 행으로 나타나요.

! 행을 보존해도 결과 행 수가 같지는 않을 수 있어요

학생 LEFT JOIN 수강은 S105의 미수강 행을 남기면서 S101·S106의 2건씩 수강도 각각 남기므로 6명에서 8행으로 늘어납니다. LEFT JOIN이 1대1만 보장하는 것은 아닙니다.

06

06. 조건 없이 두 표를 모두 섞으면?

CROSS JOIN은 왼쪽의 모든 행과 오른쪽의 모든 행을 하나씩 짝지어 조합을 만들어요. 학생 6행과 학과 3행이라면 6×3 = 18행입니다. 조인 조건이 없어도 되는 경우에 쓰지만, 실수로 조건을 빠뜨려 많은 행이 나올 때도 같은 원리가 적용돼요.

↳ 결합과 실제 소속은 다릅니다

CROSS JOIN으로 생긴 S101-D20 조합은 수학적인 가능한 짝일 뿐 S101이 D20 소속이라는 뜻은 아니에요. 학과를 정확히 붙이려면 결합 조건을 추가해야 합니다.

! 성능과 결과값을 모두 점검

전체 조합 18행을 뽑은 뒤 조건으로 5행만 남길 수도 있지만, 이 단원에서는 의미가 분명한 JOIN ... ON을 추천합니다. SQLite는 CROSS JOIN에 별도 최적화 의미도 있으므로 DBMS별 실행계획까지 일반화하지 않아요.

07

07. 학생→수강→강좌, 세 표를 연결해 봐요

학생 표에는 학생 이름, 수강 표에는 누가 어떤 강좌를 신청했는지, 강좌 표에는 강좌 이름이 있어요. 학생→수강은 student_id, 수강→강좌는 course_id로 차례로 연결합니다. 각 연결마다 필요한 조건을 빠뜨리지 않는 것이 중요해요.

08

08. 학생은 여섯 명인데 결과는 왜 일곱 줄일까요?

JOIN 결과는 기본적으로 일치하는 행의 조합 수입니다. S101은 두 강좌, S106도 두 강좌를 신청했으므로 학생 ID가 결과에 여러 번 나와요. 중복된 학생 ID가 있다고 조인 결과가 잘못된 것은 아닙니다.

↳ 학생 수와 수강 건수는 서로 다른 질문

COUNT(*)는 학생×수강의 일치 행 수인 7을 세고, COUNT(DISTINCT s.student_id)는 연결된 고유 학생 5명을 세어요. 수강이 없는 학생까지 알고 싶다면 LEFT JOIN 후 COUNT(e.enrollment_id)를 사용하면 0건도 나타낼 수 있습니다.

! COUNT(*)와 COUNT(오른쪽 열) 차이

LEFT JOIN에서 수강 기록이 없는 학생은 오른쪽 열이 NULL인 가상 행 하나로 남아요. 따라서 학생별 COUNT(*)는 1 이상일 수 있지만 COUNT(e.enrollment_id)는 0을 반환합니다. 질문에 맞는 집계를 선택하세요.

09

09. 조인이 이상하게 많거나 적게 나올 때

원래 학생 6명과 수강 7건은 조건 없이 조합하면 42행이 됩니다. 정확한 학생 ID로 연결하면 7행이에요. 반대로 INNER JOIN에서 연결되지 않은 행을 의도치 않게 제외했는지도 확인해야 합니다.

10

10. 전체 SQL과 결과표를 직접 재현해요

빈 SQLite 데이터베이스에서 학생·학과·강좌·수강·시간구간 표를 생성한 다음 30개 SELECT를 그대로 실행할 수 있어요. 화면의 모든 결과표는 검증한 열 이름·행 순서·NULL 값을 보여 줍니다.

↳ 실습 범위와 DBMS

교육용 조회는 SQLite에서 검증합니다. NULL 표시는 결과 화면에서 보이기 쉽게 쓴 것이고 실제 SQL 값은 NULL이에요. Oracle, PostgreSQL에서의 별도 실행은 확인하지 않았으며 각 DBMS의 문법·타입 차이는 후속 검수 대상입니다.

12

12. 조인 핵심을 다시 정리해요

  • 조인은 여러 테이블의 행을 결합 조건에 따라 연결한 결과를 만듭니다.
  • 동등 조인은 =, 비동등 조인은 범위·부등호 등으로 연결합니다.
  • INNER JOIN은 일치하는 행만, LEFT JOIN은 왼쪽 행을 모두 보존합니다.
  • CROSS JOIN은 행 수를 곱한 모든 조합을 만듭니다.
  • 1:N 연결에서는 한 학생이 여러 행으로 나타날 수 있습니다.
  • NULL은 일반적인 = 비교에서 매칭되지 않습니다.
  • JOIN 결과의 학생 수, 전체 행 수, 원본 테이블 행 수는 다른 개념입니다.
↳ 실전 판단법

연결 키 → 보존할 표 → 1:N 여부 → 중복/NULL → 최종 행 수 순서로 따라가면 JOIN 문제를 차근차근 풀 수 있어요. ORDER BY가 없으면 결과 행 순서는 보장되지 않는다는 06Q 내용도 함께 기억하세요.
