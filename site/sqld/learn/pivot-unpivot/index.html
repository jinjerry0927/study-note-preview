행을 열로, 열을 행으로 바꾸면? PIVOT 절과 UNPIVOT 절

06Y에서는 같은 테이블을 연결해 계층을 따라갔어요. 이번에는 데이터가 놓인 방향을 바꿔 분기별 판매 실적을 비교하고, 그 결과를 다시 목록으로 펼쳐 보겠습니다.

PIVOT은 범주를 열로 바꾸면서 집계하고, UNPIVOT은 열을 행으로 펼칩니다. 그룹 키와 NULL 정책에 따라 행 수가 달라지며, 합쳐진 원본 거래는 단순 UNPIVOT으로 복원되지 않습니다. DBMS별 구문도 구분해야 합니다.

01

01. 판매 기록을 분기별 비교표로 바꾸려면?

판매 11건이 하나씩 쌓인 표에서는 서울의 Q1·Q2·Q3 매출을 한눈에 비교하기 어렵습니다. PIVOT은 분기 *값*을 새 *열*로 배열하면서 매출을 집계해 비교표로 만듭니다. 반대 방향으로 분기 열을 행으로 펼치는 것이 UNPIVOT입니다.

02

02. Long ↔ Wide: 무엇이 행이고 열일까요?

Long 형식은 region, quarter, amount를 한 행에 저장합니다. Wide 형식은 지역별로 한 행을 만들고 q1, q2, q3처럼 분기가 열 머리글이 됩니다. 구조가 회전했지만 단순 위치 교환만 있는 것은 아니며, 동일 지역·분기 행 여러 건은 집계해야 합니다.

Q1~Q3만 집계한 Wide 결과
지역Q1 합계Q2 합계Q3 합계
대전40SQL NULL (행 없음)20
부산90030
서울15080SQL NULL (입력값 NULL)
↳ 먼저 세기

원본은 11행이고 Wide는 3행입니다. 서울 Q1=100+50=150, 부산 Q1=70+20=90입니다. 서울 Q4=10은 선택한 열 목록 밖입니다.

! 정확한 표현

Wide의 NULL만 보고 원본 값이 NULL이었는지, 관련 원본 행이 없었는지는 구별할 수 없습니다.

03

03. PIVOT은 회전하면서 집계합니다

Oracle에서는 PIVOT (SUM(amount) FOR quarter IN ('Q1' AS q1, 'Q2' AS q2, 'Q3' AS q3))처럼 집계 대상·가로로 놓을 열·출력할 범주를 지정합니다. SQLD 문제에서는 어떤 열이 생성되는지와 몇 행이 묶이는지를 먼저 확인하세요.

SQLite는 이 PIVOT 문법을 직접 지원하지 않으므로 조건부 집계로 동일한 목표를 실습합니다. SQL: SELECT region, SUM(CASE WHEN quarter='Q1' THEN amount END) AS q1, SUM(CASE WHEN quarter='Q2' THEN amount END) AS q2, SUM(CASE WHEN quarter='Q3' THEN amount END) AS q3 FROM sales_long GROUP BY region ORDER BY region;

↳ 직접 확인

B1은 대전 40/NULL/20, 부산 90/0/30, 서울 150/80/NULL의 3행입니다. SUM은 NULL이 아닌 값만 합칩니다.

! 원형 SQL과 실습 SQL 구분

B1은 Oracle PIVOT 문법을 SQLite에서 실행한 사례가 아닙니다. Oracle 원형 문법은 별도 참고 SQL 파일에 제공하며 실제 Oracle 서버 실행은 미진행입니다.

04

04. COUNT와 AVG를 쓰면 어떤 값이 될까요?

같은 회전이라도 집계 함수가 바뀌면 값이 달라집니다. SUM은 금액을 더하고, AVG는 비NULL 금액의 평균을 구합니다. **COUNT(*)는 원본 행을 세고, COUNT(amount)**는 NULL이 아닌 금액만 셉니다.

서울의 분기별 입력과 집계
분기원본 판매행SUM(amount)COUNT(*)COUNT(amount)
Q1100·5015022
Q2808011
Q3SQL NULLSQL NULL10
Q4 (제외)101011
↳ SQLite 실습 B2

COUNT(CASE WHEN quarter='Q3' THEN 1 END)은 서울 Q3의 존재하는 행 1건을 셉니다. 반면 COUNT(CASE WHEN quarter='Q3' THEN amount END)은 0건입니다.

! COUNT(*)의 위치

피벗 후 전체 COUNT(*)는 결과 행 수를 세며, 피벗 과정에서 분기별 COUNT를 계산하는 것과 다릅니다.

05

05. PIVOT 결과 행 수는 무엇이 결정하나요?

Oracle의 PIVOT은 절에서 소비한 피벗 열·집계 대상 외의 남은 입력 열을 암묵적 그룹 키로 삼습니다. 예를 들어 입력에 region, channel, quarter, amount가 있으면 분기·금액 이외에 region과 channel 두 열이 남아 지역×채널별 행이 됩니다.

입력 투영에 따른 예상 행 수
피벗 입력남는 그룹 키예제 결과
region, quarter, amountregion3행
region, channel, quarter, amountregion, channel6행
sale_id, region, channel, quarter, amountsale_id, region, channel판매 ID별로 분리될 수 있음
↳ 의도한 그룹만 남기기

Oracle에서 FROM (SELECT region, quarter, amount FROM sales_long) PIVOT (...)처럼 안쪽 SELECT로 입력 열을 명시하면 나도 모르게 행이 쪼개지는 문제를 피할 수 있습니다.

! 오개념

PIVOT을 쓰기만 하면 무조건 지역별 한 행이 되는 것이 아닙니다. 입력에 sale_id 같은 고유값이 남으면 각 원본 행이 개별 그룹이 될 수 있습니다.

06

06. UNPIVOT은 열을 여러 행으로 펼칩니다

UNPIVOT은 q1, q2, q3를 `quarter` 값과 `amount` 값의 행으로 펼칩니다. Oracle 예: UNPIVOT (amount FOR quarter IN (q1 AS 'Q1', q2 AS 'Q2', q3 AS 'Q3')). SQLite에는 직접 구문이 없으므로 UNION ALL 세 갈래로 대응 결과를 재현합니다.

UNPIVOT 기본 NULL 제외 결과 7행

원래는 3지역×3분기=9칸입니다. NULL 두 칸이 제거되고 7행이 출력됩니다. 실제 값 0은 NULL이 아니므로 남습니다.

! SQL Server 문법도 주의

SQL Server UNPIVOT도 NULL 입력 칸을 결과에서 제외합니다. Oracle의 INCLUDE NULLS 선택지는 같은 문법으로 SQL Server에서 사용하지 않습니다.

07

07. NULL 제외와 INCLUDE NULLS는 어떻게 다를까요?

Oracle UNPIVOT은 기본적으로 `EXCLUDE NULLS`이며, INCLUDE NULLS를 명시하면 NULL 칸도 펼칩니다. SQLite 대응 예제 D2/D3을 비교하면 기본 NULL 제외 7행, NULL 포함 9행입니다.

NULL·0·행 부재를 비교
조건원본 Long피벗 WideUNPIVOT 기본
부산 Q20인 행 있음0보존
서울 Q3NULL인 행 있음NULL제외
대전 Q2원본 행 없음NULL제외

SUM(CASE WHEN quarter='Q2' THEN amount END)와 SUM(CASE WHEN quarter='Q2' THEN amount ELSE 0 END)는 같지 않습니다. 후자는 Q2 값이 없더라도 다른 분기의 0을 더하므로 대전의 빈 칸을 0으로 만들 수 있습니다.

! 시험 함정

값 0은 제외되지 않습니다. 또한 피벗 결과의 NULL만으로 원본 NULL과 행 부재를 복원할 수 없습니다.

08

08. PIVOT 뒤 UNPIVOT하면 원본이 돌아올까요?

항상 돌아오지 않습니다. PIVOT은 집계를 하면서 sale_id와 개별 판매액을 합칠 수 있습니다. 서울 Q1의 100과 50은 하나의 150이 되어, UNPIVOT 후에도 두 거래가 무엇이었는지 알 수 없습니다.

되돌릴 수 없는 행 수 차이
단계행 수이유
Long 원본11Q4 1건 포함, NULL 금액 1건 포함
Q1~Q3 비NULL 원본9Q4 1건과 NULL 금액 1건 제외
PIVOT(SUM) 후 UNPIVOT EXCLUDE7동일 그룹 중복 거래가 합쳐짐
↳ 보존되는 것/보존되지 않는 것

Q1~Q3 금액 총합 410은 유지되지만 판매 건별 ID와 원본 건수는 유지되지 않습니다. 합계 보존과 원본 행 복원은 별개의 성질입니다.

! 정확성

UNPIVOT은 PIVOT의 수학적인 완전 역함수가 아닙니다. 피벗 원본에 집계·NULL·제외된 범주가 있었다면 특히 그렇습니다.

09

09. 어떤 분기를 열로 만들고, 어떻게 이름 붙이나요?

정적 피벗에서는 IN 목록에 기재한 범주가 결과 열이 됩니다. Q1~Q3을 지정하면 Q4=10은 표시되지 않습니다. Q5처럼 원본에 없는 분기를 지정하더라도 해당 결과 열의 집계값은 NULL이 될 수 있습니다.

↳ 같은 데이터의 다른 질문

B5는 Q4까지 만들고, G5는 존재하지 않는 Q5 열도 만듭니다. 열 수는 선택한 범주 수, 행 수는 그룹 키별 묶음 수에 따라 달라집니다.

! 정렬

PIVOT 자체가 최종 출력 순서를 보장하는 것은 아닙니다. 결과를 순서대로 설명하려면 ORDER BY region처럼 명시하세요.

10

10. Oracle과 다른 DBMS의 문법 차이

Oracle과 SQL Server는 PIVOT·UNPIVOT 절을 지원하지만 서로 구문과 NULL 처리 옵션이 완전히 동일한 것은 아닙니다. SQLite와 일반 PostgreSQL SELECT에는 똑같은 전용 절이 없으므로 조건부 집계·UNION ALL을 사용하거나 PostgreSQL의 확장 tablefunc.crosstab 등을 선택합니다.

문법 비교 — 별도 파일의 예시를 함께 확인
DBMS행→열열→행·NULL

SQL ServerPIVOT ... FOR ... IN ([Q1], ...)UNPIVOT, NULL 칸 제외
PostgreSQLSUM(...) FILTER (WHERE ...), tablefunc.crosstabUNION ALL 등

! 실행 구분

이 패키지의 자동 재현 40개는 SQLite로 실행했습니다. Oracle·SQL Server·PostgreSQL 원형 SQL은 문서 기반 참고 예시이며 실서버 실행 결과로 단정하지 않습니다.

12. PIVOT과 UNPIVOT 핵심 요약

  • PIVOT은 행의 범주를 새 열로 만들면서 집계합니다.
  • PIVOT 결과 행 수는 암묵적/명시적 그룹 키에 달려 있습니다.
  • UNPIVOT은 열을 행으로 펼치며 Oracle의 기본값은 EXCLUDE NULLS입니다.
  • 0은 남고 NULL은 기본적으로 제외됩니다. NULL과 입력 행 부재는 다릅니다.
  • PIVOT 후 UNPIVOT은 원본 행·중복·식별자를 복원하지 못할 수 있습니다.
  • SQLite 실습 코드는 조건부 집계·UNION ALL 대응 방식이며 Oracle 전용 원형 SQL과 다릅니다.
↳ 기억을 돕는 비공식 요령
