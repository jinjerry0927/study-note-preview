DMLData Manipulation Language

개념부터 차근차근!

학생 기록을 추가·수정·삭제해 볼까요? DML

앞 단원까지 SQL로 데이터를 조회하고 가공했어요. 이번에는 학생 기록이 실제로 바뀌는 과정을 안전한 실습 DB에서 연습합니다.

INSERT는 행 추가, UPDATE는 기존 값 수정, DELETE는 행 제거입니다. WHERE 누락의 영향을 실제 결과로 확인하고, MERGE 조건 분기·제약 위반·COMMIT/ROLLBACK을 구분하세요.

이 단원을 끝내면

  1. 1DML을 INSERT·UPDATE·DELETE·MERGE로 구별하고 SELECT 분류 차이를 설명한다.
  2. 2INSERT VALUES와 INSERT SELECT가 추가하는 행 수를 계산한다.
  3. 3생략된 열의 DEFAULT와 명시 NULL·NOT NULL 제약을 구별한다.
  4. 4UPDATE의 WHERE·SET 계산과 영향 행 수를 판단한다.
  5. 5DELETE의 WHERE 유무·IS NULL 조건을 판단하고 TRUNCATE/DROP과 구별한다.
  6. 6MERGE의 매칭 분기와 SQLite UPSERT의 제한적인 대응 관계를 구별한다.
  7. 7PRIMARY KEY/NOT NULL/CHECK/FOREIGN KEY와 ROLLBACK/COMMIT 효과를 구분한다.
학습 기록을 불러오는 중이에요.
01

01. 학생 기록을 추가하거나 고치고 삭제한다면?

지난 단원들은 주로 데이터를 조회했어요. DML(Data Manipulation Language, 데이터 조작어)은 이미 존재하는 테이블의 행을 삽입(INSERT)·변경(UPDATE)·삭제(DELETE)하는 명령입니다. 조건에 따라 변경을 선택하는 MERGE도 배웁니다.

이번 단원에서 사용하는 가상 학생 명단(변경 전 5행)
학생 ID이름부서시간메모상태
S101민지D105SQL NULLactive
S102준호D207기초active
S103서연D108복습paused
S104지훈D209SQL NULLactive
S105유나SQL NULL6SQL NULLactive
명령의 큰 분류
명령목적예
SELECT결과 조회SELECT ... FROM ...
INSERT행 추가INSERT INTO ... VALUES ...
UPDATE기존 행 값 수정UPDATE ... SET ... WHERE ...
DELETE행 제거DELETE FROM ... WHERE ...
MERGE매칭 결과에 따른 삽입·수정·삭제MERGE INTO ... USING ...
! 분류 용어는 문맥에 따라 다를 수 있어요

SELECT는 자료·교육 과정에 따라 DML에 넓게 포함하기도 하고 DQL(데이터 질의어)로 별도 구분하기도 합니다. SQLD 학습에서는 데이터를 바꾸는 명령과 조회 전용 명령의 역할 차이를 먼저 이해하세요.

02

02. INSERT는 새 행을 추가해요

INSERT INTO 테이블(열 목록) VALUES (값 목록)은 지정한 열에 값을 넣어 새로운 행을 추가합니다. 열 목록과 값의 순서·개수가 맞아야 해요.

예: A2 — 학생 S108 추가
변경 전명령변경 후
S108 없음INSERT ... VALUES ('S108','현우','D10',2)S108 / 현우 / D10 / 2 추가
↳ 기억하세요

열 목록을 적으면 스키마 열 순서를 암기하지 않아도 되며, 선택적으로 열을 생략할 수 있어요.

! 실수하기 쉬워요

INSERT는 기존 같은 PK를 덮어쓰는 명령이 아닙니다. S101을 다시 넣으면 기본적으로 UNIQUE/PRIMARY KEY 오류가 납니다(B2).

03

03. 값을 생략할 때와 NULL을 명시할 때

열을 생략하면 해당 열의 DEFAULT가 있으면 그 기본값, 없으면 일반적으로 NULL을 넣습니다. 반면 NULL을 명시적으로 넣으면 기본값을 대신 쓰지 않습니다. 단, NOT NULL 제약이 있으면 NULL은 허용되지 않습니다.

study_students 열 규칙
열제약·기본값생략했을 때
study_hoursNOT NULL DEFAULT 00
statusNOT NULL DEFAULT 'active'active
memoNULL 허용, 기본값 없음SQL NULL
department_id외래키, NULL 허용SQL NULL
student_nameNOT NULL, 기본값 없음오류

A3에서 학생 이름만 주면 시간 0·상태 active가 채워집니다. E2의 DEFAULT VALUES는 별도의 기본값이 정의된 보조 테이블에서 실험합니다.

! 실수하기 쉬워요

NULL은 문자열 'NULL'이 아닙니다. WHERE 열 = NULL 대신 IS NULL을 사용하세요. 데이터 형식과 제약은 DBMS별로 차이가 있습니다.

04

04. INSERT ... SELECT로 여러 행을 한 번에

INSERT INTO 대상(열 목록) SELECT 열 목록 FROM 원본은 SELECT가 돌려준 행을 대상으로 옮겨 담습니다. VALUES로 직접 쓸 필요 없이 여러 행을 한번에 삽입할 수 있어요.

A5: incoming_students → study_students
원본 학생원본 시간삽입 후 학생 행 수
S106 하늘45 → 7
S107 다은35 → 7
↳ 기억하세요

삽입 열과 SELECT 출력 열의 개수·대응 순서·타입 호환성을 확인하세요. SQL의 SELECT는 반환 순서를 보장하지 않으며 결과 확인은 별도 ORDER BY를 사용합니다.

! 실수하기 쉬워요

키 중복·외래키 위반·NOT NULL 위반이 있으면 삽입이 실패할 수 있습니다. 교육 시나리오는 서로 독립된 빈 DB에서 매번 초기화합니다.

05

05. UPDATE는 WHERE에 맞는 행을 수정해요

UPDATE 테이블 SET 열 = 값 WHERE 조건은 기존 행의 값을 수정합니다. WHERE 조건이 맞는 행만 바뀌고, 조건이 없으면 대상 테이블의 모든 행이 UPDATE 대상이 됩니다.

C1·C2·C3의 수정 범위
코드조건영향 행
C1student_id = S1011명
C2department_id = D202명
C3WHERE 없음5명 전체
! 실수하기 쉬워요

조건을 쓰지 않으면 의도치 않게 전부 수정할 수 있습니다. 실제 서비스에서는 수정 전 동일 WHERE를 사용한 SELECT/COUNT와 트랜잭션 전략을 검토하세요.

06

06. 기존 값으로 계산하거나 조건 없이 0행 수정

SET study_hours = study_hours + 2는 각 대상 행의 기존 값을 바탕으로 수정합니다. C4에서는 D10의 민지 5→7, 서연 8→10이 됩니다.

C5존재하지 않는 S999 대상으로 수정0행 변경

값을 계산하는 UPDATE도 행 단위 조건에 따라 실행됩니다. 잘못된 CHECK·NOT NULL·외래키 제약을 위반할 수 있습니다.

07

07. DELETE는 행을 지워요

DELETE FROM 테이블 WHERE 조건은 행 전체를 제거합니다. UPDATE가 열 값만 고치는 것과 달라요. WHERE가 없으면 모든 행이 삭제 대상이 됩니다.

D1~D5 결과
코드제거 대상남은 행 수
D1S1034
D2D20 소속 두 명3
D3전체0
D4S999(없음)5
D5부서가 SQL NULL인 S1054
! 실수하기 쉬워요

DELETE 후 조회에서 안 보인다는 사실이 자동 COMMIT을 뜻하지 않습니다. 트랜잭션 확정·취소는 DBMS와 설정에 따라 다르고 다음 TCL 단원에서 자세히 배웁니다.

08

08. DELETE·TRUNCATE·DROP은 같은가요?

DELETE는 행을 지우는 DML입니다. TRUNCATE TABLE은 테이블 데이터를 빠르게 제거하는 관리 명령으로, 트랜잭션·제약·롤백·트리거 동작이 DBMS에 따라 다릅니다. DROP TABLE은 테이블 구조 자체를 없애는 DDL입니다.

비교 기준
명령대상WHERE 사용테이블 정의
DELETE조건에 맞는 행가능유지
TRUNCATE테이블의 전체 행일반적으로 불가유지
DROP테이블 객체불가제거
↳ 기억하세요

Oracle의 TRUNCATE와 PostgreSQL의 TRUNCATE는 트랜잭션 취급 등이 다르므로 하나의 DBMS 규칙을 일반화하지 않습니다.

! 실수하기 쉬워요

SQLite에는 Oracle 방식의 TRUNCATE TABLE 구문이 없습니다. 이번 SQLite 실습의 D3 DELETE FROM을 TRUNCATE 원형 실행으로 혼동하지 마세요.

09

09. MERGE는 조건에 따라 INSERT 또는 UPDATE

MERGE는 원본(source)과 대상(target)을 ON 조건으로 비교한 뒤 MATCHED → UPDATE, NOT MATCHED → INSERT 등 지정한 동작을 실행합니다. Oracle/PostgreSQL에서 원형 MERGE를 사용해 설명합니다.

같은 결과를 얻기 위한 비교
원본 학생 ID대상에 존재?분기
S102예UPDATE
S211아니요INSERT

SQLite는 일반적인 MERGE 문법 대신 `INSERT ... ON CONFLICT DO UPDATE`(UPSERT)를 사용합니다. 다만 UPSERT는 PRIMARY KEY/UNIQUE 충돌이 조건이고 MERGE는 임의의 ON 조인 조건을 기준으로 하므로 동일한 명령이 아닙니다.

! 실수하기 쉬워요

같은 대상 행을 여러 원본 행이 동시에 갱신하려 하면 DBMS에 따라 오류·제약 문제가 생깁니다. 이 예제는 학생 ID가 유일하다는 가정을 둡니다.

10

10. 무결성 제약과 COMMIT·ROLLBACK

DML이 실행된다고 해서 언제나 성공하는 것은 아닙니다. PRIMARY KEY, NOT NULL, CHECK, FOREIGN KEY 등의 제약이 새 값의 무결성을 지킵니다. SQLite 실습에서는 PRAGMA foreign_keys=ON을 설정합니다.

실패 시나리오와 이유
코드실패 조건예상 오류
B2PRIMARY KEY 중복UNIQUE constraint failed
B3이름 NULLNOT NULL constraint failed
B4학습시간 -1CHECK constraint failed
B5존재하지 않는 D99FOREIGN KEY constraint failed

ROLLBACK은 미확정 변경을 취소하고 COMMIT은 트랜잭션을 확정합니다. G4는 S101의 5→99 변경을 ROLLBACK해서 다시 5, G5는 COMMIT해서 99를 조회합니다.

! 실수하기 쉬워요

SQLite 예제의 트랜잭션 시맨틱을 모든 DBMS로 확대하지 마세요. Oracle의 DDL 자동 커밋·PostgreSQL TRUNCATE 등은 별도로 다룹니다.

12

12. DML 핵심 정리

  • INSERT: 새 행을 추가한다. 열을 생략하면 DEFAULT 또는 NULL이 적용된다.
  • UPDATE: 기존 행을 수정한다. WHERE가 없으면 모든 행이 대상이다.
  • DELETE: 행을 제거한다. WHERE가 없으면 전체 행이 대상이다.
  • MERGE: 원본·대상 매칭에 따라 조건부 변경을 수행한다. SQLite UPSERT와 원리가 완전히 같지는 않다.
  • 무결성 제약은 잘못된 DML을 거부할 수 있다. COMMIT/ROLLBACK은 변경 확정과 취소를 담당한다.
  • SELECT는 조회이고 DML/DQL 분류는 자료마다 다를 수 있다. TRUNCATE/DROP은 DELETE와 다르다.
↳ 기억하세요
