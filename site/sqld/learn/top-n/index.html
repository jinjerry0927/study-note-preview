Top N 쿼리Top-N Queries

개념부터 차근차근!

누가 가장 앞에 올까요? Top N 쿼리

06Q에서는 정렬을, 06W에서는 순위 함수의 동작을 배웠어요. 이제 판매 8건 중 필요한 위쪽 행만 정확히 선택하면서 DBMS별 Top N 문법과 동률·페이지 이동 함정을 확인할 거예요.

Top N = 정렬 기준 + 선택 행 수(+ 동률 정책). Oracle ROWNUM은 정렬 순위가 아니고, OFFSET은 먼저 건너뛰는 수예요. WITH TIES는 끝 위치의 공동 정렬값을 포함하며, 그룹별 Top N은 PARTITION BY로 분리해야 해요.

이 단원을 끝내면

  1. 1정렬 기준과 N을 먼저 정해야 하는 이유를 8행 예제에서 설명한다.
  2. 2Oracle ROWNUM과 ROW_NUMBER의 차이 및 같은 쿼리 블록 ORDER BY의 함정을 설명한다.
  3. 3Oracle 정렬 인라인 뷰 + 바깥 ROWNUM과 ROW_NUMBER 필터의 결과를 비교한다.
  4. 4Oracle/PostgreSQL FETCH FIRST·OFFSET과 SQL Server TOP을 방언별로 구분한다.
  5. 5WITH TIES가 금액 정렬에서 4행이 되고 고유 보조 키를 넣으면 2행이 되는 이유를 추적한다.
  6. 6SQLite/PostgreSQL LIMIT·OFFSET의 페이지 범위를 정확히 계산한다.
  7. 7ROW_NUMBER/RANK/DENSE_RANK로 행 수·공동 순위·서로 다른 점수 등급을 구분한다.
  8. 8PARTITION BY를 이용해 지역별 상위 N행과 그룹별 동점 포함 결과를 계산한다.
  9. 9NULL·WHERE 필터·동점·데이터 변경 시 Top N/페이지 의미의 경계를 설명한다.
  10. 10검증용 SQLite SQL과 Oracle/SQL Server/PostgreSQL 문서 기반 예제를 구별한다.
학습 기록을 불러오는 중이에요.
01

01. 성적표처럼 판매 기록에서 몇 건만 볼까요?

학교에서 "점수가 가장 높은 3명"을 찾거나, 쇼핑몰에서 "판매금액 상위 2건"만 보고 싶다면 모든 행을 출력할 필요가 없어요. Top N 쿼리는 먼저 원하는 기준으로 순위를 정의한 뒤 그 결과 중 일부 행을 선택하는 SQL을 말합니다. 여기서 N은 가져올 행 수이고, 동점도 함께 보여 줄 것인지는 별도로 정해야 해요.

06W에서 사용한 가상 판매 8건 — 이번 단원도 같은 입력값
sale_idregioncategoryamount
1서울책100
2서울문구50
3부산책80
4부산문구20
5SQL NULL책30
6서울책80
7부산책80
8서울문구50

금액만 보면 100이 한 행, 80이 세 행, 50이 두 행, 30과 20이 각 한 행이에요. 따라서 "상위 2행"은 2행이지만, "2위와 같은 금액까지 모두"는 4행이 될 수 있습니다.

↳ 앞에서 배운 내용과의 연결

06Q ORDER BY에서는 정렬의 방향과 NULL 위치를, 06W 윈도우 함수에서는 ROW_NUMBER·RANK·DENSE_RANK를 배웠어요. 이번 단원은 정렬과 잘라내기를 합쳐 실제 조회하는 방법을 배우며, 이미 배운 개념은 필요한 부분만 짧게 재사용해요.

! 실습 DBMS와 다른 문법을 구별해요

A1~H5의 40개 쿼리는 SQLite에서 직접 실행했습니다. 각 절의 대표 SQL에는 DBMS와 검증 근거를 표시합니다. Oracle 19c·PostgreSQL 18·SQL Server의 원형 SQL은 공식 문서로 대조했으며 실서버 실행은 아직 확인하지 않았습니다.

02

02. 상위 N은 정렬 기준부터 정해야 해요

SELECT sale_id,amount FROM sales ORDER BY amount DESC,sale_id ASC LIMIT 2;는 금액이 큰 순서, 금액이 같으면 sale_id 작은 순서를 결정한 뒤 앞의 2행을 출력해요. 실제 결과는 (1,100), (3,80)입니다. ORDER BY가 없는 LIMIT 2는 "최고 금액 2건"을 의미하지 않아요.

↳ 상위 3행도 동점 모두가 아니에요

A3: LIMIT 3은 1·3·6번 3행만 출력해요. 7번도 80이지만 자동으로 추가되지 않습니다. 동점 포함은 별도의 WITH TIES 또는 RANK 같은 규칙이 필요해요.

! 정렬과 보조 정렬은 다릅니다

ORDER BY amount DESC만 적으면 금액이 80인 세 행의 내부 순서는 보장되지 않습니다. 재현 가능한 정확한 2행이나 페이지를 원한다면 sale_id 같은 고유 보조 키를 추가하세요.

03

03. Oracle ROWNUM은 정렬 순위가 아니에요

Oracle의 ROWNUM은 쿼리 블록에서 행을 선택하면서 붙는 가상 열이에요. WHERE ROWNUM <= 2 ORDER BY amount DESC라고 쓰면 상위 금액 2건을 보장하지 않습니다. 같은 블록에서 ROWNUM으로 2행을 먼저 제한한 다음 그 두 행만 정렬할 수 있기 때문이에요. 실제로 어떤 행을 먼저 읽을지는 인덱스·계획에 따라 달라집니다.

설명용 명시적 접근 순서 시뮬레이션
방식결과 sale_id주의
ID순 2행 선발 뒤 금액정렬 (B2)1,2의도한 금액 상위 2가 아님
금액순 Top 2 (A2)1,3정렬 기준에 맞는 상위 2

Oracle에서 단일 쿼리 블록의 WHERE ROWNUM > 1은 0행입니다. 첫 행은 계속 ROWNUM=1로 평가되어 조건을 통과하지 못하기 때문이에요. 반면 B4는 SQLite의 이미 계산된 ROW_NUMBER 결과를 rn>1로 필터해 7행을 보여 줍니다. 두 개념은 같지 않다는 대비를 위한 실습이에요.

! B1~B5는 Oracle 실행이 아닙니다

B1~B3과 B5는 SQLite에서 정렬과 선발의 선후를 설명합니다. 예를 들어 B2는 먼저 ID 1·2를 읽도록 정한 설명용 사례예요. Oracle은 실제 행 접근 순서에 따라 다른 행을 읽을 수 있습니다. 위 원형 SQL과 B4의 계산된 순번도 구분해서 보세요.

04

04. 정렬하고 나서 잘라야 해요

Oracle에서 ROWNUM으로 상위 2행을 고르려면 안쪽 인라인 뷰에서 정렬하고, 바깥 SELECT에서 `ROWNUM <= 2`를 적용합니다. 바깥 ORDER BY까지 쓰면 골라 낸 두 행의 출력 순서도 확정됩니다.

C2는 안쪽 SELECT에서 ROW_NUMBER() OVER(ORDER BY amount DESC, sale_id)로 순번을 만들고 바깥 WHERE rn <= 2에서 ID 1·3을 고릅니다. 같은 구조로 WHERE rn BETWEEN 3 AND 4를 적용한 C3은 ID 6·7을 반환합니다.

↳ ROW_NUMBER와 ROWNUM은 이름만 비슷해요

ROW_NUMBER는 OVER(ORDER BY ...)의 순서를 명시하는 분석 함수이고, ROWNUM은 Oracle의 행 선택 시 생성되는 가상 열입니다. 특히 행 3~4번 선택은 분석 함수/별도 정렬 계층으로 구현하는 편이 명확해요.

! 인라인 정렬만으로 최종 표시 순서를 보장하지 않아요

안쪽 ORDER BY는 Top N의 선발 기준을 정의합니다. 최종 출력 순서는 바깥쪽 ORDER BY로 확정하는 습관을 들이세요. C그룹은 SQLite의 결과 확인을 위해 바깥 정렬을 명시합니다.

05

05. FETCH FIRST와 OFFSET은 무엇을 뜻할까요?

Oracle과 PostgreSQL은 ORDER BY amount DESC,sale_id OFFSET 2 ROWS FETCH NEXT 2 ROWS ONLY처럼 건너뛸 수와 가져올 수를 표현할 수 있어요. OFFSET 2는 앞의 2행을 건너뛰고, FETCH NEXT 2 ROWS ONLY는 최대 2행을 가져온다는 뜻입니다. 같은 데이터에서 D2는 6·7번을 반환합니다.

FETCH FIRST 2 ROWS WITH TIES는 마지막으로 뽑힌 위치와 ORDER BY 기준이 동률인 행을 추가해요. ORDER BY amount DESC라면 100원 한 행과 80원 세 행, 총 4행이 됩니다. 반대로 ORDER BY amount DESC,sale_id는 각 행이 고유하므로 2행만 반환합니다.

동률 포함의 정확한 조건
정렬 기준상위 2행WITH TIES 결과
amount DESC1, (80 중 1)1,3,6,7 : 4행
amount DESC, sale_id ASC1,31,3 : 2행
↳ SQLite 대응과 원형 SQL

D3의 SQLite 재현은 RANK() OVER (ORDER BY amount DESC)에서 경계 동률을 계산합니다. 바깥 ORDER BY amount DESC, sale_id는 이미 고른 결과의 표시 순서만 고정해요. D4에서는 창 안에도 sale_id를 넣어 동률 키 자체를 바꿉니다.

! WITH TIES와 전체 순서

동률을 추가하더라도 그 동률 그룹 내부의 선후까지 자동 결정하지 않아요. 행 표시를 확정하는 추가 정렬과 동률 판정에 사용하는 원래 ORDER BY 목록을 혼동하지 마세요.

06

06. SQL Server에서는 TOP을 사용해요

SQL Server는 SELECT TOP (2) sale_id,amount FROM ... ORDER BY amount DESC,sale_id;처럼 SELECT 뒤에 TOP을 적어요. TOP (2)는 최대 두 행이고, TOP (2) WITH TIES는 ORDER BY 경계의 동률 행을 더 반환할 수 있습니다. WITH TIES를 쓰려면 ORDER BY가 필요합니다.

E2는 금액만 비교한 4행, E3은 고유 ID도 비교한 2행을 SQLite로 재현합니다. E4는 기존 8행의 25%인 2행을 반환합니다. 독립 7행 예시의 25%는 1.75이며, SQL Server의 PERCENT 규칙에 따라 올림해 2행을 예상합니다.

↳ 서로 다른 질문입니다

TOP (2)로 판매행 2개를 선택하는 것과 SELECT DISTINCT amount ...로 서로 다른 금액 2개를 선택하는 것은 다릅니다. E5의 금액 100·80은 두 등급이지 판매 2건을 의미하지 않습니다.

! SQL Server OFFSET/FETCH 위치

SQL Server의 OFFSET/FETCH는 ORDER BY 아래에 쓰고, 같은 SELECT 범위에 TOP과 OFFSET/FETCH를 함께 사용할 수 없습니다. FETCH ... WITH TIES는 SQL Server의 ORDER BY OFFSET/FETCH 문법에서 지원되지 않으므로 TOP WITH TIES와 구분하세요.

07

07. LIMIT과 OFFSET은 어떻게 페이지를 자를까요?

SQLite와 PostgreSQL에서 ORDER BY amount DESC,sale_id LIMIT 2 OFFSET 2는 상위부터 두 행을 건너뛴 뒤 두 행을 반환합니다. 첫 페이지가 1·3번이라면 다음 페이지는 6·7번이에요. LIMIT 2 OFFSET 6은 마지막 5·4번, OFFSET 8은 0행이에요.

정렬된 전체 8행 기준 페이지
범위SQLite 구문반환 sale_id
1~2LIMIT 2 OFFSET 01,3
3~4LIMIT 2 OFFSET 26,7
5~6LIMIT 2 OFFSET 42,8
7~8LIMIT 2 OFFSET 65,4
9~10LIMIT 2 OFFSET 8(없음)
↳ OFFSET부터 적용

OFFSET 2는 반환할 2행이 아니라 건너뛸 행 수입니다. 따라서 LIMIT 2 OFFSET 2는 2번째부터가 아니라 3번째부터 두 행입니다.

! LIMIT 자체가 정렬을 대신하지 않아요

ORDER BY amount DESC에 동률이 있으면 페이지를 넘길 때 같은 금액의 행이 서로 다른 페이지에 나타날 순서가 안정적이지 않습니다. 고유 보조 키를 넣고 데이터 변경 여부도 고려하세요.

08

08. 공동 2등까지 포함할까요, 딱 2행만 볼까요?

Top N은 질문을 정확히 해야 해요. "정확히 두 판매행"이라면 고유한 정렬 + LIMIT/ROW_NUMBER를 선택합니다. "2위까지 공동 순위 모두"라면 RANK <= 2, "상위 2개 금액 등급"이라면 DENSE_RANK <= 2처럼 목표를 분리하세요.

금액 100·80×3·50×2·30·20에서 차이
조건반환 행 수이유
ROW_NUMBER ≤ 22고유 위치 1·2
RANK ≤ 24공동 2위 80 세 건
RANK ≤ 343위는 없고 다음은 5위
DENSE_RANK ≤ 36상위 금액 등급 100/80/50 전체
! RANK와 고유 보조 정렬을 혼용하지 마세요

RANK() OVER(ORDER BY amount DESC,sale_id)라면 sale_id가 모두 달라 공동 순위가 사라집니다. 동률을 유지하려면 RANK의 창 ORDER BY에는 amount DESC만 사용하고, 최종 SELECT 출력에 sale_id를 보조 정렬로 둘 수 있어요.

09

09. 지역마다 상위 두 건을 뽑으려면?

LIMIT 2를 한 번 쓰면 전체에서 두 행만 가져와요. 지역별 2건을 원하면 ROW_NUMBER() OVER(PARTITION BY region ORDER BY amount DESC,sale_id)처럼 지역마다 번호를 다시 계산하고, 바깥에서 rn <= 2를 필터링해야 합니다.

H1 실제 결과는 서울 2건(1·6), 부산 2건(3·7), NULL 지역 1건(5)으로 5행입니다. 반대로 H2의 지역별 RANK 1위는 서울 1건(1), 부산 공동 1위 두 건(3·7), NULL 지역 1건(5)으로 4행이에요.

↳ 그룹별 서로 다른 금액 등급도 가능

같은 1위 조건으로 비교하면 ROW_NUMBER ≤ 1은 지역마다 1행씩 총 3행, RANK ≤ 1은 부산 공동 1위를 포함해 4행입니다. H3의 DENSE_RANK ≤ 2는 지역별로 금액 등급 두 개를 골라 총 6행을 반환합니다.

! WHERE에서 윈도우 별칭을 바로 필터하지 마세요

WHERE rn<=2와 같은 조건은 ROW_NUMBER() AS rn을 정의한 같은 SELECT의 WHERE에 바로 넣을 수 없어요. 인라인 뷰/CTE에서 계산하고 바깥 SELECT에서 필터해야 합니다.

10

10. NULL·필터·페이지 이동도 따져 볼까요?

판매 ID 5의 지역은 SQL NULL입니다. Top N 실습에서 amount는 NOT NULL이지만, 지역별 Top N에서는 지역 NULL 한 행도 하나의 파티션으로 계산합니다(H1/H4). NULL은 0이나 텍스트 "NULL"이 아니고, DBMS마다 NULL 기본 정렬 위치가 다르므로 필요할 때 CASE/IS NULL을 명시하세요.

WHERE region='서울' ORDER BY amount DESC,sale_id LIMIT 2 OFFSET 1(F5)은 먼저 서울 행 4개로 좁힌 뒤 첫 행을 건너뛰어 6·2번을 반환합니다. WHERE를 전체 Top N 적용 후에 하는 것과 결과가 달라져요.

보충 학습 · 페이지 일관성과 키셋 탐색. 고유 정렬 키는 같은 입력에서 순서를 고정합니다. 별도 조회 사이에 행이 추가·삭제되면 OFFSET 위치가 밀려 중복·누락이 생길 수 있습니다. 예를 들어 첫 페이지를 읽은 뒤 120원 판매가 앞에 추가되면, OFFSET 2에서 이미 본 ID 3을 다시 읽습니다. H5는 마지막 정렬 키 (80, 3)보다 뒤의 행을 WHERE로 고른 후 LIMIT 2를 적용해 ID 6·7을 반환합니다.

12. Top N 핵심을 한 장으로 정리

  • Top N은 정렬 기준을 확정하고 필요한 행만 선택하는 작업이다. ORDER BY가 없으면 정렬된 "상위"를 보장할 수 없다.
  • 정확히 N행: SQLite/PostgreSQL LIMIT N, Oracle FETCH FIRST N ROWS ONLY, SQL Server TOP(N) 등. 부족하면 실제 있는 행만.
  • Oracle ROWNUM은 정렬 순위가 아니다. 같은 쿼리 블록에서 ROWNUM으로 먼저 제한하고 ORDER BY로 정렬하면 금액 기준 상위 N은 보장되지 않는다. 정렬 인라인 뷰와 바깥 ROWNUM을 활용한다.
  • 동률 포함: WITH TIES는 ORDER BY 전체 키 기준이다. 경계의 공동 점수를 모두 포함하면 출력 행 수가 N보다 많아질 수 있다.
  • OFFSET은 행을 먼저 건너뛰는 수이다. LIMIT 2 OFFSET 2 = 위치 3·4. 고유 보조 정렬이 없으면 페이지 결과가 흔들릴 수 있다.
  • 정확히 N행/동률까지/상위 N개 서로 다른 금액 등급은 ROW_NUMBER/RANK/DENSE_RANK로 구분한다.
  • 그룹마다 N행을 뽑으려면 PARTITION BY에서 번호를 계산하고 바깥에서 필터한다.
  • SQL은 DBMS마다 위치와 문법이 다르며, 모사한 SQLite 결과와 원형 Oracle/SQL Server/PostgreSQL 서버 검증은 구별한다.
↳ 시험에서 먼저 체크

① 무엇으로 정렬하는가 ② 동률을 더 포함하는가 ③ 먼저 건너뛰는 행은 몇 개인가 ④ 전체인가 그룹별인가 ⑤ 어떤 DBMS 문법인가 순서로 문제를 읽어 보세요.
