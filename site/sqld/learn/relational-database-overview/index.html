개념부터 차근차근!

테이블은 어떻게 연결되고, SQL은 무엇을 할까요?

앞서 만든 학생·강좌·신청 데이터는 실제 데이터베이스에서 어떤 모양으로 저장될까요? 테이블 구조와 무결성, SQL 명령의 전체 지도를 먼저 익혀요.

RDBMS는 관계형 모델에 따라 데이터를 테이블로 다루는 DBMS예요. 행·열, PK·FK 같은 제약, SQL의 조회·변경 명령을 구별하면 다음 SELECT 학습이 쉬워져요. SQL은 집합 개념을 쓰지만 중복 행과 DBMS 차이를 반드시 따져야 합니다.

이 단원을 끝내면

  1. 1DB(데이터), DBMS(관리 소프트웨어), RDBMS(관계형 DBMS)를 구별해요.
  2. 2테이블의 행·열·값과 PK·FK·UNIQUE·NOT NULL이 보장하는 규칙을 설명해요.
  3. 3학생·신청·강좌 테이블의 PK/FK 연결을 읽고 참조 무결성과 JOIN을 구별해요.
  4. 4SQL의 DQL/DML/DDL/DCL/TCL 분류를 예시와 함께 설명하고 관례·DBMS 지원 차이를 알아요.
  5. 5선택·투영·DISTINCT·UNION 등 집합 개념과 SQL 중복 행 허용, DBMS별 자료형·문법 차이를 이해해요.
학습 기록을 불러오는 중이에요.
01

01. 학생·강좌·신청 정보가 한 표에 뒤섞여 있다면?

학생 S101이 C01과 C02에 신청했어요. 학생명·강좌명·신청ID를 한 표에 계속 복사하면 학생명 수정이나 강좌 정보 변경 시 같은 값을 여러 곳에서 고쳐야 할 수 있습니다. 학생·강좌·신청을 각각의 테이블로 나누고 필요한 순간 연결하면 의미를 더 명확하게 관리할 수 있어요.

앞선 06H~06K에서 사용한 수강신청 세 건
신청ID학생ID강좌ID
E501S101C01
E502S101C02
E503S102C02
↳ 학습 연결

06H의 JOIN, 06K의 PK와 UNIQUE를 실무 SQL 용어로 다시 만나요. 이번 단원은 테이블·무결성·SQL의 큰 지도를 이해하는 입문이며, 상세 SELECT 문법은 다음 06M 「SELECT 문」에서 공부합니다.

02

02. 데이터베이스·DBMS·RDBMS는 어떻게 다를까요?

데이터베이스(DB)는 관련 데이터를 조직적으로 저장·관리하는 데이터의 모음이고, DBMS는 그 데이터를 정의·저장·조회·수정하고 접근을 관리하는 소프트웨어예요. RDBMS는 관계형 데이터 모델을 기반으로 테이블과 SQL 등의 기능을 제공하는 DBMS 종류입니다.

이름이 비슷한 용어를 구별해요
용어쉽게 설명이 예시에서는
Database저장·관리되는 데이터의 집합학생·강좌·신청 데이터
DBMS데이터를 관리하는 소프트웨어SQLite·PostgreSQL·Oracle 같은 제품
RDBMS관계형 모델을 사용하는 DBMS표와 키를 이용해 자료를 다루는 시스템
SQLDBMS에 요청을 표현하는 언어SELECT로 조회, INSERT로 추가
! 주의: 관계형의 뜻

관계형 데이터베이스의 관계(Relation)는 단지 테이블 사이에 선(FK)이 있다는 뜻이 아니라 데이터를 논리적 관계(테이블 형태)로 표현하는 모델을 가리킵니다.

03

03. 테이블의 행·열·값은 무엇일까요?

테이블(Table)은 같은 종류의 대상을 행과 열로 표현해요. 행(Row, 튜플)은 한 대상의 기록이고, 열(Column, 속성)은 그 기록의 항목입니다. 행과 열이 만나는 칸에는 값이 들어가며, 각 열에는 자료형과 제약을 정의할 수 있습니다.

예시: 학생 테이블 study_students (총 3행, 3열)
student_idstudent_namedepartment_id
S101민지D10
S102준호D20
S103민지D10

민지라는 이름은 두 행에서 반복되지만 학생ID S101과 S103은 다릅니다. 열 이름은 속성의 의미, 행은 서로 다른 학생 기록을 표현합니다.

! 행 순서를 가정하지 마세요

테이블에 데이터를 넣은 순서대로 조회 결과가 나온다고 보장되지 않습니다. 조회 결과 순서가 중요하면 ORDER BY를 명시해야 합니다.

04

04. PK·FK·UNIQUE·NOT NULL이 하는 일

무결성(Integrity)은 데이터가 업무 규칙과 제약에 맞도록 유지되는 성질입니다. 제약조건은 잘못된 값과 잘못된 참조를 DBMS 수준에서 제한해요. 앞 단원의 식별자와 관계 개념이 CREATE TABLE의 제약조건으로 연결됩니다.

자주 쓰는 제약조건
제약조건검사하는 내용수강신청 예시
PRIMARY KEY행을 유일하게 식별, NULL 불가enrollment_id
FOREIGN KEY참조 값이 부모의 허용된 키에 존재student_id → 학생
UNIQUE지정 열 또는 열 조합의 중복 제한(student_id, course_id)
NOT NULL반드시 값이 존재해야 함학생ID·강좌ID
CHECK조건식 결과가 FALSE인 입력 거부 (UNKNOWN은 통과할 수 있음)score BETWEEN 0 AND 100 등
! 중요한 경계

FK는 다른 테이블을 조회할 때 자동으로 JOIN해 주는 명령이 아닙니다. FK는 참조 무결성 제약, JOIN은 데이터를 결합해 조회하는 SQL 연산이에요. 또한 UNIQUE의 NULL 취급은 DBMS별로 다르므로 필수 속성에는 NOT NULL을 별도 검토하세요.

05

05. 학생·신청·강좌가 연결되는 구조

학생 테이블의 PK는 student_id, 강좌 테이블의 PK는 course_id예요. 수강신청 테이블이 두 PK를 FK로 참조하므로 어느 학생이 어떤 강좌를 신청했는지 표현할 수 있습니다. 참조하는 학생과 강좌가 없으면, 이 예제의 FK 제약 아래에서는 해당 신청을 저장할 수 없어요.

수강신청 데이터
enrollment_idstudent_id (FK)course_id (FK)
E501S101C01
E502S101C02
E503S102C02

S103은 아직 신청이 없지만 학생 테이블에 존재할 수 있어요. 학생을 보존하는 LEFT JOIN 조회에서 S103의 신청 열이 NULL이 되는 상황은 06H에서 다뤘습니다.

↳ 이번 단원의 범위

여기서는 PK·FK 관계를 해석하는 데 집중합니다. JOIN의 종류·ON/WHERE 차이는 06H에서 복습할 수 있고, 2과목 표준 조인 단원에서 다시 다룹니다.

06

06. SQL 명령어는 무슨 일을 할까요?

SQL(Structured Query Language)은 관계형 데이터베이스에 구조를 정의하고 데이터를 조회·변경하며, 권한·트랜잭션을 관리할 때 사용하는 선언적 언어입니다. 어떤 일을 요청할지 표현한다는 것이 핵심입니다.

학습에 유용한 5분류
범주기능대표 명령
DQL데이터 조회SELECT
DML데이터 삽입·수정·삭제INSERT / UPDATE / DELETE
DDL객체 구조 정의·변경CREATE / ALTER / DROP / TRUNCATE
DCL권한 관리GRANT / REVOKE
TCL트랜잭션 경계 제어COMMIT / ROLLBACK / SAVEPOINT
! 분류와 실제 명령은 구별

DQL을 독립 분류하는 것은 교육용 관례이며, SELECT를 DML에 포함하는 체계도 있습니다. 또한 SQLite는 GRANT·REVOKE·TRUNCATE TABLE을 같은 형태로 지원하지 않으므로, 이 표의 모든 명령을 SQLite에서 실행할 수 있는 것은 아닙니다. 트랜잭션·DDL의 자동 커밋 등은 DBMS별로 달라요.

07

07. 선택·투영·집합 연산은 무엇일까요?

관계 대수에서 선택(Selection, σ)은 조건을 만족하는 행을, 투영(Projection, π)은 원하는 열을 고릅니다. SQL에서는 WHERE와 SELECT 열 목록으로 유사한 결과를 만들지만, 수학적 관계의 집합 의미와 실제 SQL의 중복 행 허용은 구별해야 합니다.

학생 테이블의 학과ID는 D10, D20, D10입니다. SQL에서 SELECT department_id는 D10을 두 번 반환할 수 있고, SELECT DISTINCT department_id는 D10과 D20을 한 번씩 반환합니다. 관계 대수의 전통적인 투영은 중복 없는 집합을 전제로 한다는 차이를 기억하세요.

두 신청 학생 집합의 예
집합/연산학생ID 결과
A: C01 수강생S101
B: C02 수강생S101, S102
A UNION BS101, S102
A INTERSECT BS101
B EXCEPT AS102
! 시험 오개념

SQL의 UNION은 중복 제거, UNION ALL은 중복 보존입니다. Oracle에서는 차집합에 MINUS를 사용하며, Oracle Database 26ai는 EXCEPT도 지원합니다. 결과 순서는 ORDER BY 없이는 보장되지 않습니다. 이 단원에서는 직관만 익히고 집합 연산자 상세 문법은 뒤 단원에서 학습합니다.

08

08. SQLite·PostgreSQL·Oracle에서 SQL이 똑같을까요?

관계형 모델과 기본 SQL의 목적은 비슷해도 자료형 이름·문자열 처리·날짜·제약 실행 방식·특수 SQL 문법은 DBMS에 따라 달라요. 이번 페이지의 실행 예시는 SQLite 3.x로 고정해 결과를 검증합니다.

대표적인 방언 차이 — 간략 예시
주제SQLite 3.xPostgreSQLOracle Database
문자 자료TEXTTEXT / VARCHARVARCHAR2
정수 자료INTEGERINTEGERNUMBER 등
날짜 저장/형식전용 DATE 저장 클래스 없음; TEXT/REAL/INTEGER 방식DATE / TIMESTAMPDATE / TIMESTAMP
공백 없는 빈 문자열길이 0의 TEXT 값길이 0의 문자열일반적으로 NULL 취급

특정 버전의 함수·자료형·문법과 NULL·자동 커밋 처리는 차이가 있습니다. 예제의 원리와 실제 실행 DBMS를 구분하고, 다른 DBMS로 옮길 때 해당 제품의 문서를 확인하세요.

09

09. 작은 데이터베이스를 SQL로 읽어 봐요

이제 학생 3명 + 강좌 2개 + 신청 3건을 SQLite 3.x의 새 빈 데이터베이스에서 직접 만들어 봅니다. 아래의 전체 SQL은 테이블 생성 → 데이터 삽입 → LEFT JOIN·DISTINCT 조회까지 순서대로 실행할 수 있어요. 실행 결과는 바로 아래 표와 비교하세요.

SQL 문장과 기대 결과
쿼리 요약기대 결과
SELECT student_id FROM study_students WHERE department_id = 'D10'S101, S103 (2행)
SELECT DISTINCT department_id FROM study_studentsD10, D20 (2행)
학생·신청·강좌 INNER JOINE501, E502, E503 (3행)
학생 LEFT JOIN 신청S103을 포함한 4행 (S103 신청ID NULL)
존재하지 않는 학생 S999로 INSERTFK 오류, 저장 거부
  • 테이블: 학생/강좌/신청의 기록을 분리합니다.
  • 제약: PK·FK·UNIQUE·NOT NULL로 유일성과 참조를 보호합니다.
  • 조회: WHERE로 행을 선택하고 SELECT로 표시 열을 정하며 JOIN으로 연결합니다.
  • 집합: SELECT DISTINCT와 UNION/INTERSECT/EXCEPT의 중복·집합 처리를 구별합니다.
↳ 실행 환경과 주의

도식은 미리 검증한 SQL 결과를 보여 주는 교육용 시뮬레이션입니다. 브라우저에서 SQL을 실시간으로 실행하는 것은 아니에요. 새 빈 SQLite 3.x 데이터베이스에서 코드 전체를 실행하면 동일한 표를 재현할 수 있습니다. 기존 DB에서 같은 CREATE TABLE 문장을 반복 실행하면 테이블이 이미 존재한다는 오류가 날 수 있어요. 기존 SQL 검증 스크립트도 별도로 보존합니다.

10

10. 관계형 데이터베이스 개요 핵심 요약

  • DB(저장된 데이터) / DBMS(관리 소프트웨어) / RDBMS(관계형 DBMS)는 같은 말이 아닙니다.
  • 테이블=행과 열: 행은 기록, 열은 속성. 같은 이름은 중복될 수 있고 PK로 대상을 식별합니다.
  • PK/UNIQUE/NOT NULL/FK는 서로 다른 무결성 규칙입니다. FK는 자동 JOIN이 아닙니다.
  • SQL의 SELECT·INSERT/UPDATE/DELETE·CREATE·GRANT·COMMIT은 요청 목적이 다르고, 분류 체계와 실행 가능 DBMS도 구분해야 합니다.
  • WHERE는 행 선택, SELECT 열 목록은 열 선택에 해당하며 SQL은 기본적으로 중복 행을 허용합니다. DISTINCT와 UNION ALL을 구별하세요.
  • 자료형·NULL·집합 연산자 이름 등은 DBMS·버전에 따라 차이가 있습니다.
