GROUP BY, HAVING 절GROUP BY & HAVING

개념부터 차근차근!

같은 값을 묶고, 그룹 결과를 골라볼까요?

06O에서는 WHERE로 필요한 행을 골랐어요. 이제 같은 학과끼리 묶고, 각 그룹의 학생 수와 보너스 점수 합계를 계산한 뒤, 원하는 그룹만 남겨 봅니다.

WHERE는 행을 먼저 선택, GROUP BY는 같은 기준의 행을 묶음, HAVING은 집계 조건으로 그룹 선택, ORDER BY는 최종 출력 정렬을 담당해요. COUNT(*)와 COUNT(열)은 NULL 처리에서 다르고, GROUP BY는 정렬을 보장하지 않습니다.

이 단원을 끝내면

  1. 1COUNT(*)·COUNT(열)·COUNT(DISTINCT 열)의 NULL·중복 처리 차이를 말해요.
  2. 2SUM·AVG·MIN·MAX의 NULL 처리와 AVG의 분모를 계산해요.
  3. 3GROUP BY로 그룹이 만들어지는 원리와 NULL 그룹을 설명해요.
  4. 4SELECT에서 그룹 기준 열과 집계 함수의 사용 규칙을 구분해요.
  5. 5WHERE가 그룹화 전에 행을, HAVING이 그룹화 후 그룹을 거르는 차이를 실습해요.
  6. 6GROUP BY·HAVING·SELECT·ORDER BY를 결합해 결과 행을 예측해요.
  7. 7빈 입력에서 집계 결과 한 행과 그룹 결과 0행을 구별해요.
학습 기록을 불러오는 중이에요.
01

01. 여섯 줄을 학과별 한 줄로 요약한다면?

06O WHERE 절에서는 조건에 맞는 학생 행만 선택했어요. 이번에는 여러 행을 학과별로 묶어 각 학과의 학생 수와 합계·평균을 계산해 봅니다. 명단에서 사람을 고르는 것이 WHERE라면, 같은 학과 학생들을 묶어 학과별 결과표를 만드는 것이 GROUP BY예요.

02

02. COUNT(*)와 COUNT(열)는 무엇이 다를까요?

COUNT(*)는 조건을 통과한 행 자체의 개수를 세고, COUNT(bonus_points)는 보너스 값이 NULL이 아닌 행만 세요. 값이 0인 행은 NULL이 아니므로 포함합니다. COUNT(DISTINCT department_id)는 중복과 NULL을 제외하고 서로 다른 학과 값의 개수를 셉니다.

같은 D20 그룹도 COUNT 대상에 따라 다릅니다

D20은 2행이므로 COUNT(*)=2지만, S102의 점수는 NULL이라 COUNT(bonus_points)=1입니다. 0점인 S104는 셉니다.

C4에서는 보너스 값 10, 20, 0이 서로 달라 COUNT(bonus_points)와 COUNT(DISTINCT bonus_points)가 모두 3입니다. DISTINCT는 중복된 값을 한 번만 세는 것이라서, 실제 중복된 학생 이름으로도 비교해 보세요. 학생 6명의 이름에는 민지가 두 번 등장합니다. COUNT(student_name)=6이지만 COUNT(DISTINCT student_name)=5입니다. C4 도식 아래에 두 이름 집계 SQL을 별도 실습으로 표시합니다.

03

03. SUM·AVG·MIN·MAX와 NULL을 이해해요

집계 함수는 여러 행에서 하나의 요약값을 만듭니다. SUM은 합계, AVG는 평균, MIN과 MAX는 최솟값·최댓값이에요. 일반적인 숫자 집계에서 NULL은 계산에서 빠지고, AVG의 분모도 NULL이 아닌 값의 개수입니다.

D10의 보너스 값은 10, 20, NULL입니다. SUM=30, AVG=15이고 AVG(COALESCE(bonus_points, 0))=10으로 바뀝니다. NULL을 0으로 채우면 원래 빠졌던 한 행이 평균의 분모에 추가되기 때문입니다.

! NULL과 0을 동일하게 계산하면 안 됩니다

D20 보너스 값 NULL, 0에서는 SUM=0, AVG=0입니다. 반면 S105처럼 전부 NULL인 그룹의 SUM·AVG·MIN·MAX는 SQL NULL을 반환합니다. COUNT(열)만 0입니다.

04

04. GROUP BY는 어떤 기준으로 묶을까요?

GROUP BY department_id는 같은 학과 값을 가진 학생을 한 그룹에 모아요. 여기서는 D10 학생 3명, D20 학생 2명, NULL 학과 학생 1명으로 그룹 3개가 생깁니다. 그룹마다 COUNT(*)를 계산하면 그룹당 결과 한 행이 만들어져요.

↳ NULL 학과도 그룹이 됩니다

GROUP BY에서는 같은 그룹화 키를 가진 행을 묶으며, NULL 키 행도 하나의 NULL 그룹으로 묶습니다. 이는 WHERE department_id = NULL이 TRUE가 된다는 뜻이 아닙니다. 그룹화와 값 비교의 규칙을 구분하세요.

GROUP BY는 집계 함수를 반드시 써야 하는 명령은 아닙니다. SELECT department_id FROM ... GROUP BY department_id처럼 그룹 키만 출력하면 여기서는 학과 값 세 종류가 나옵니다. 다만 이 단원에서는 집계 원리를 이해하는 데 집중해요.

05

05. 그룹 쿼리에서 어떤 열을 SELECT할 수 있을까요?

그룹별 결과를 만들 때는 보통 GROUP BY에 적은 기준 열과 COUNT·SUM처럼 집계한 결과를 SELECT에 사용합니다. SELECT department_id, COUNT(*) ... GROUP BY department_id는 안전한 기본형이에요. 반면 한 학과에 여러 이름이 있으면 student_name을 그대로 출력했을 때 어느 이름을 골라야 할지 정해져 있지 않습니다.

! SQLite가 실행해 준다고 모든 DBMS에서 유효한 SQL은 아닙니다

SELECT department_id, student_name, COUNT(*) FROM study_students GROUP BY department_id는 SQLite에서 그룹 내 임의 행의 이름을 반환할 수 있지만 일반적인 SQL 학습 규칙으로 사용하면 안 됩니다. Oracle 등에서는 그룹에 포함되지 않은 비집계 열이 오류 원인이 됩니다. 일부 DBMS에는 함수 종속성 예외가 있으므로 모든 DBMS가 절대 같다고 단정하지 않습니다.

↳ 여러 그룹 기준

학과와 보너스 점수를 함께 구분하고 싶다면 GROUP BY department_id, bonus_points처럼 두 기준을 모두 사용합니다. SUM(study_hours)와 MAX(study_hours)는 그룹 안의 여러 값에서 하나의 집계값을 계산합니다.

06

06. WHERE는 그룹을 만들기 전에 행을 거릅니다

WHERE study_hours >= 8을 먼저 적용하면 S103(8시간), S104(9시간), S106(10시간) 세 행만 남습니다. 그 상태에서 학과별로 묶으면 D10은 2명, D20은 1명이 됩니다. 원본의 D10=3명, D20=2명과 달라지죠.

! WHERE에 집계 결과를 바로 넣지 않아요

WHERE COUNT(*) >= 2는 올바른 그룹별 필터가 아닙니다. WHERE는 그룹화 전 각 행의 조건을 다루고, 집계된 그룹의 개수를 제한하려면 HAVING COUNT(*) >= 2를 사용합니다.

07

07. HAVING은 만들어진 그룹을 골라냅니다

HAVING은 그룹이 만들어지고 집계된 뒤 그룹 전체에 적용하는 조건입니다. 전체 6명에서 HAVING COUNT(*) >= 2는 D10(3명)과 D20(2명)을 남기고 NULL 학과(1명)는 제거합니다.

집계 조건은 그룹별 합계나 값의 존재 여부에도 적용할 수 있어요. HAVING SUM(bonus_points) > 0은 D10만 남깁니다. HAVING COUNT(bonus_points) = 0은 보너스 점수가 전부 NULL인 NULL 학과 그룹을 남깁니다.

↳ GROUP BY 없이 HAVING도 가능한 경우

집계 함수가 사용되면 GROUP BY가 없어도 전체 입력을 하나의 집계 그룹으로 볼 수 있습니다. SELECT COUNT(*) FROM study_students HAVING COUNT(*) >= 6은 한 행을 반환합니다. SQLite에서는 3.39 이상에서 이 구문을 실행할 수 있어요.

08

08. WHERE와 HAVING을 함께 사용하면?

다음 SQL을 단계별로 읽어 봅시다. WHERE study_hours >= 8 → GROUP BY department_id → HAVING COUNT(*) >= 2. 먼저 S103·S104·S106을 고른 다음 D10(2명), D20(1명)으로 묶고, 마지막에는 D10 한 그룹만 남습니다.

↳ 물리적 실행 순서를 보장하는 그림이 아닙니다

FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY는 결과를 이해하는 논리적 설명 순서입니다. DBMS의 실제 물리적 실행 계획이 반드시 같은 순서를 따른다는 뜻은 아닙니다.

비슷해 보여도 WHERE 기준을 study_hours >= 7로 바꾸면 D10(2명)과 D20(2명)이 모두 남아요. 조건을 적용하는 단계와 경곗값이 결과를 바꾼다는 점을 확인하세요.

09

09. 그룹 결과를 출력하고 정렬해요

SELECT에는 그룹 기준 열과 계산한 집계값을 명확하게 적고, ORDER BY로 최종 결과 행의 표시 순서를 정해요. GROUP BY 자체에는 출력 정렬 보장이 없습니다. COUNT(*) AS student_count로 별칭을 준 뒤 ORDER BY student_count DESC를 사용할 수 있습니다.

↳ NULL 정렬은 제품별 차이 주의

NULL 그룹을 결과에 포함할 때 DBMS 기본 NULL 정렬 위치는 같지 않을 수 있어요. 이 단원의 NULL 그룹 조회는 ORDER BY CASE WHEN department_id IS NULL THEN 1 ELSE 0 END, department_id로 재현 순서를 분명히 합니다. SQLite 전용 불리언 정렬을 보편 문법이라고 가르치지 않습니다.

10

10. 아무 행도 없을 때 결과는 어떻게 다를까요?

WHERE study_hours > 99를 만족하는 학생은 없어요. 이때 GROUP BY 없는 집계 SELECT COUNT(*), SUM(bonus_points)는 한 행을 반환하며 각각 0, NULL이 됩니다. 반면 같은 WHERE 뒤에 GROUP BY department_id를 붙이면 만들어질 그룹이 없어 결과 행이 0개입니다.

! 결과의 0과 NULL과 행 0개는 모두 다릅니다

COUNT(*)=0인 결과 한 행, SUM(...) IS NULL인 결과 한 행, 그리고 아예 반환 행이 0개인 경우를 구별해야 합니다. 테스트에서도 행 수와 각 셀 값을 분리해 검증합니다.

↳ E1·E2와 E3·E4는 결과가 사라지는 이유부터 다릅니다

E1·E2는 WHERE에 맞는 입력이 0행인 비교입니다. E1은 GROUP BY 없는 전체 집계라 COUNT(*)=0·SUM=NULL인 결과 한 행, E2는 GROUP BY로 만들 그룹이 없어 결과 0행입니다. E3·E4는 입력이 6행이고 GROUP BY 없는 집계를 하나의 그룹으로 본 다음 HAVING으로 거릅니다. COUNT(*)>=6인 E3은 한 행을 남기고, COUNT(*)>6인 E4는 그룹이 조건을 만족하지 못해 결과 0행입니다. SQLite에서 E3·E4 실습은 3.39 이상을 사용하세요.

11

11. 전체 SQL을 복사해서 다시 검증해요

앞의 각 도식에서 본 SQL을 새 빈 SQLite 메모리 데이터베이스에 그대로 생성·삽입한 뒤 순서대로 실행해 볼 수 있어요. 각 번호 쿼리의 열 이름·결과 행·NULL 표기를 검증했고, 원본 5명과 새 학생 1명의 가상 예제 경계도 기록했습니다.

↳ DBMS 구분

표의 NULL 표기는 사람이 읽기 위한 표시입니다. Oracle/PostgreSQL 실기기에서 직접 실행했다고 주장하지 않으며, 이 실습은 SQLite 3.39 이상이 필요해요.

12

12. GROUP BY와 HAVING 핵심 요약

  • COUNT(는 행 수, COUNT(열)**은 NULL이 아닌 값 수예요. 0은 셉니다.
  • SUM·AVG·MIN·MAX는 일반적으로 NULL을 제외합니다. 입력이 전부 NULL이면 결과가 NULL일 수 있습니다.
  • GROUP BY는 같은 키의 행을 그룹으로 묶고, 보통 그룹별 한 행을 출력해요. NULL 키도 한 그룹이 됩니다.
  • 그룹 SELECT는 그룹 키와 집계 결과 중심으로 작성하세요. SQLite의 비집계 bare column 관용을 일반화하지 않아요.
  • WHERE는 행을 먼저 선별, HAVING은 집계 후 그룹 선별입니다.
  • ORDER BY가 최종 결과의 정렬 순서를 명시합니다. GROUP BY는 정렬 명령이 아닙니다.
  • 빈 입력에서 GROUP BY 없는 COUNT(*) 결과 한 행(0)과 GROUP BY 결과 0행을 구분하세요.
↳ 연결 학습

06O WHERE 절에서 배운 행 조건과, 다음 06Q ORDER BY 절에서 다룰 정렬을 연결해 복습하세요.
