SQL 함수는 데이터를 어떻게 바꿔 보여 줄까요?

06M에서는 SELECT로 열을 골랐어요. 이번에는 값을 그대로 보여 주는 대신, 함수로 대문자 변환·반올림·날짜 계산·NULL 대체·조건별 라벨 붙이기까지 해 봅니다.

단일행 함수는 각 입력 행의 값에 적용하고, 집계 함수는 여러 행을 요약합니다. 문자열·숫자·날짜·형변환 함수는 DBMS별 문법과 데이터형을 확인해야 해요. NULL은 0이 아니고, COALESCE와 NULLIF는 서로 다른 일을 합니다. CASE는 위에서부터 조건에 따라 값을 결정해요.

이 단원을 끝내면

  1. 1단일행 함수와 집계 함수의 결과 행 수 차이를 설명해요.
  2. 2UPPER·SUBSTR·TRIM으로 문자열 결과를 읽어요.
  3. 3ROUND·TRUNC·MOD의 차이와 SQLite 대체 표현의 범위를 구별해요.
  4. 4고정 날짜 계산을 실행하고 DBMS별 날짜 함수 차이를 확인해요.
  5. 5CAST와 Oracle TO_CHAR 등 형변환 함수의 역할을 구별해요.
  6. 6NULL·0과 COALESCE·NVL·NULLIF의 결과를 비교해요.
  7. 7CASE 표현식에서 먼저 만족하는 조건의 결과를 찾아요.
  8. 8함수 중첩의 안쪽→바깥쪽 평가 원리를 이해해요.
  9. 9Oracle·SQL Server·SQLite 간 문법 차이를 복사해 실행할 때 주의해요.
학습 기록을 불러오는 중이에요.
01

01. SELECT에 함수를 사용하는 이유

이전 06M에서 SELECT student_name으로 이름을 그대로 보여 주었죠. 이제 TRIM으로 공백을 제거하고 UPPER로 대문자로 표시할 수 있어요. 함수는 값을 받아 결과값을 만들어 내는 식이며, 단순한 SELECT 조회는 원본 저장값을 바꾸지 않아요.

02

02. 단일행 함수와 집계 함수는 무엇이 다를까요?

단일행 함수는 입력된 각 행에 대해 해당 결과값을 계산해요. 반면 집계 함수 COUNT, SUM, AVG 등은 여러 행을 함께 요약합니다. 예를 들어 학생 3명의 UPPER(...)는 각 학생마다 결과를 보여 주지만 COUNT(*)는 그룹화 없이 한 개의 요약 행을 반환해요.

집계 예시
COUNT(*)COUNT(bonus_points)SUM(study_hours)
3220
! COUNT(*)과 COUNT(열)는 다를 수 있어요

COUNT(*)는 모든 행을 세고, COUNT(bonus_points)는 NULL이 아닌 값만 셉니다. S102의 bonus_points는 NULL이고 S103의 값 0은 NULL이 아니므로 각각 3과 2가 돼요. GROUP BY는 별도 단원에서 배웁니다.

03

03. 문자열 함수로 공백과 대소문자를 바꿔 볼까요?

TRIM은 앞뒤 공백을 지우고, UPPER/LOWER는 대소문자를 변환하며, SUBSTR(문자열, 시작 위치, 길이)는 문자열 일부를 잘라요. 기본 위치는 1부터 세며 SUBSTR('ABCDE',2,3)은 BCD입니다.

SQLite의 ASCII 코드 값 예시
입력함수결과
sql TRIMsql
sqlUPPERSQL
ABCDESUBSTR(...,2,3)BCD
! SQLite UPPER의 비ASCII 처리

SQLite 기본 내장 UPPER/LOWER는 주로 ASCII 문자를 처리합니다. 한국어 등 비ASCII 대소문자 처리에는 ICU 확장·문자셋·DBMS 설정 차이가 있으므로 일반화하지 마세요.

04

04. 반올림과 버림과 나머지는 어떻게 다를까요?

ROUND(숫자, 자리)는 반올림, Oracle의 TRUNC(숫자, 자리)는 자리 아래를 버림, Oracle의 MOD(11,4)는 나머지 3을 구해요. ROUND(15.79,1)은 15.8이고 TRUNC(15.79,1)은 15.7이에요.

! SQLite에서 TRUNC/MOD를 그대로 쓰지 않아요

SQLite에는 Oracle의 숫자 TRUNC(숫자, 자리)를 그대로 사용하는 표준 내장 함수가 없습니다. 양수 15.79의 한 자리 버림 예시만 CAST(15.79*10 AS INTEGER)/10.0으로 비교하며, 음수·큰 수까지 일반화하지 않습니다. SQLite 정수 나머지는 %로 계산합니다. SQL Server에서는 ROUND(숫자, 자리, 1)로 잘라내기를 표현할 수 있어요.

05

05. 날짜를 더하고 날짜 사이의 일수를 구하려면?

날짜는 자료형과 문법이 DBMS마다 달라요. SQLite의 DATE('2026-11-01','+7 days')는 2026-11-08을 반환합니다. JULIANDAY('2026-11-08')-JULIANDAY('2026-11-01')은 날짜 사이 간격 7일이에요.

고정 날짜 계산
기준일7일 후차이
2026-11-012026-11-087일
! 현재 날짜를 쓰지 않는 이유

CURRENT_DATE나 SYSDATE, GETDATE()는 실행한 날짜와 시간대에 따라 결과가 달라져요. 이번 학습은 결과를 정확히 비교하도록 고정 날짜를 사용합니다. SQLite의 날짜는 다른 DBMS의 DATE 자료형과 저장 방식이 같다는 뜻이 아니에요.

06

06. 문자열 12를 숫자 12로 바꾸면?

명시적 형변환은 값의 타입을 바꿔 계산하거나 표시할 때 사용해요. SQLite에서 CAST('12' AS INTEGER)+3은 15입니다. 반대로 CAST(study_hours AS TEXT)는 숫자처럼 보이는 값을 텍스트로 만들어요.

↳ Oracle·SQL Server와의 차이

Oracle은 TO_CHAR(날짜, 형식)이나 TO_NUMBER를 자주 사용하고, SQL Server는 CAST·CONVERT 등을 활용해요. 형식 문자열·변환 실패 처리·암묵적 변환은 DBMS마다 다릅니다. 여기의 실제 실행 예제는 SQLite CAST만 검증합니다.

07

07. NULL은 0과 왜 다르고 어떻게 바꾸나요?

NULL은 모름/없음을 나타내고 숫자 0은 알려진 값입니다. COALESCE(값, 대체값)은 첫 번째 NULL이 아닌 값을 반환해요. NULLIF(a,b)는 두 값이 같으면 NULL, 다르면 첫 번째 값을 반환합니다.

학생별 NULL과 0 비교
학생bonus_pointsCOALESCE(...,0)NULLIF(...,0)
S101101010
S102NULL0NULL
S10300NULL
! 이름이 같아 보여도 자료형·인수 개수가 달라요

Oracle NVL(x,y), SQL Server ISNULL(x,y), SQLite IFNULL(x,y)는 모두 NULL 대체에 쓰이지만 자료형 결정·암묵적 형변환 규칙까지 같지 않습니다. 여러 후보에서 첫 NULL이 아닌 값을 찾을 때는 COALESCE(x,y,z)를 이해해 두세요.

08

08. CASE에서 어떤 조건이 먼저 적용되나요?

CASE WHEN 조건 THEN 결과 ... ELSE 결과 END는 조건별로 다른 값을 만들어요. 위에서부터 확인하므로 겹치는 조건은 더 먼저 만족한 가지가 선택됩니다. 예를 들어 학습 시간이 8 이상이면 우수, 6 이상이면 보통, 아니면 입문으로 표시해요.

CASE 결과
student_idstudy_hourslevel_name
S1015입문
S1027보통
S1038우수
! ELSE가 없으면 어떻게 되나요?

어떤 WHEN 조건도 참이 아니고 ELSE가 없다면 결과가 NULL이 될 수 있어요. CASE는 SELECT 결과를 분류하지만 원본 study_hours를 바꾸지는 않습니다.

09

09. 함수 안에 또 다른 함수를 쓸 수 있나요?

UPPER(TRIM(alias_code))는 안쪽 TRIM으로 공백을 제거한 결과를 바깥 UPPER에 넣어요. alias_code=' sql '이라면 TRIM → 'sql', UPPER → 'SQL'입니다. 함수 호출의 인수는 계산되어 바깥 함수로 전달돼요.

↳ 모든 SQL이 물리적으로 안쪽부터 한 단계씩 실행되는 것은 아닙니다

설명은 함수의 값 의존관계를 나타냅니다. DBMS의 최적화나 단락 평가 때문에 모든 식을 실제로 언제 평가하는지는 달라질 수 있어요. COALESCE 등 일부 식은 모든 인수를 무조건 평가하지 않습니다.

10

10. Oracle과 SQL Server의 함수가 같을까요?

같은 목적이어도 함수 이름·인수 개수·자료형·날짜 문법이 다를 수 있어요. 아래 비교는 공식 문서의 문법 예시이며 Oracle·SQL Server 자체에서 직접 실행한 검증 결과가 아닙니다. SQLite 3.x에 맞춘 SQL만 실행 결과를 확인했어요.

! 다른 DBMS 문법을 SQLite에 그대로 입력하지 마세요

예: Oracle NVL, SQL Server ISNULL, SQLite IFNULL은 제품별 문법입니다. SQL Server의 ISNULL은 NULL 판단용 IS NULL 조건식과도 다릅니다. Oracle의 TRUNC와 SQL Server의 ROUND(...,...,1)도 문법·형 처리 차이가 있어요.

11

11. 새 DB에서 함수 SQL 전체를 실행해 봐요

새 빈 SQLite 3.x 데이터베이스에서 아래 SQL을 순서대로 실행하면 테이블 생성·3행 삽입부터 각 함수의 결과까지 재현할 수 있어요. 각 번호를 선택해 반환 행·열을 비교하세요. 화면 표는 실행 결과를 미리 검증한 시뮬레이션이며 브라우저에서 SQL을 실시간으로 실행하지 않습니다.

! 새 DB에서만 실행하세요

이미 동일한 study_students 테이블이 있는 데이터베이스에서 CREATE TABLE을 반복 실행하면 오류가 날 수 있습니다. 전체 SQL은 연습용 새 데이터베이스에서만 실행하도록 구성했으며 기존 12개 단원의 기록·데이터는 수정하지 않습니다.

12

12. 함수의 핵심을 한 번에 정리해요

  • 단일행 함수는 각 행의 값을 변환하고 집계 함수는 여러 행을 요약해요.
  • TRIM·UPPER·SUBSTR는 문자열 가공 함수입니다. 위치는 기본적으로 1부터 세요.
  • ROUND는 반올림, Oracle TRUNC는 버림, MOD는 나머지입니다. SQLite %와 버림 대체 표현의 한계를 구별하세요.
  • DATE·JULIANDAY는 이번 SQLite 고정 날짜 실습용이며 Oracle·SQL Server의 날짜 계산 문법과 다릅니다.
  • CAST는 명시적 형변환입니다. Oracle TO_CHAR는 출력용 형식 변환에서 자주 등장합니다.
  • COALESCE는 첫 NULL 아닌 값, NULLIF는 두 값이 같으면 NULL입니다.
  • CASE WHEN은 조건 순서가 중요하고, 함수 중첩은 안쪽 함수 결과가 바깥 함수의 인수가 됩니다.
  • DBMS 방언과 NULL·자료형 차이를 확인하고, 검증되지 않은 결과를 단정하지 마세요.
