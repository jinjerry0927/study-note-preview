표준 조인Standard SQL JOIN

개념부터 차근차근!

같은 JOIN, 다른 결과? 표준 조인 문법을 비교해요

06R에서는 조인이 왜 필요한지와 연결 결과가 왜 늘거나 줄어드는지를 배웠어요. 이번에는 JOIN 구문을 어떻게 쓰는지, 왼쪽과 오른쪽에 어느 행이 남는지, 같은 조건을 ON이나 WHERE에 두면 왜 결과가 달라지는지 직접 비교해 봅니다.

표준 JOIN은 연결 종류와 조건 위치를 명시합니다. INNER는 일치 행만, LEFT/RIGHT/FULL은 각각 보존할 쪽이 다릅니다. USING은 지정한 공통 열을 하나로 출력하고, NATURAL은 같은 이름의 모든 열을 자동으로 조건에 넣어 위험할 수 있습니다. 외부 조인에서 ON과 WHERE는 같은 효과가 아닙니다.

이 단원을 끝내면

  1. 1ANSI 표준 `JOIN ... ON`의 구조와 INNER 생략형을 구분해요.
  2. 2INNER·LEFT·RIGHT·FULL OUTER JOIN이 보존하는 행과 NULL을 결과표로 확인해요.
  3. 3`ON`의 단일·복수 조건과 LEFT JOIN에 붙인 조건의 효과를 설명해요.
  4. 4`USING(열)`의 조건과 `SELECT *` 출력 열 차이를 파악해요.
  5. 5`NATURAL JOIN`이 모든 공통 열 이름을 사용하며 스키마 변화에 민감하다는 점을 설명해요.
  6. 6`CROSS JOIN`의 반환 행 수와 `ON 1=1` 비교 결과를 계산해요.
  7. 73개 이상 테이블을 연결하고 LEFT 뒤 INNER가 미매칭 행에 미치는 영향을 예측해요.
  8. 8외부 조인의 조건을 ON과 WHERE에 배치했을 때 매칭과 보존 결과를 구별해요.

02

02. JOIN ... ON을 읽는 순서

표준 결합의 뼈대는 FROM 왼쪽표 s INNER JOIN 오른쪽표 d ON 연결조건이에요. JOIN만 적으면 INNER JOIN으로 해석됩니다. s, d는 테이블 별칭이고, ON은 어떤 행끼리 연결할지 지정해요. 테이블 별칭 앞의 AS 허용 여부는 DBMS별로 달라 06S SQL은 별칭 앞에 AS를 생략합니다.

↳ 한 줄씩 읽기

SELECT s.student_id, d.department_name FROM study_students s JOIN study_departments d ON s.department_id=d.department_id처럼 읽으면 됩니다. 예제 A1과 A2의 반환은 똑같은 5행이에요.

! 구문과 결과의 경계

콤마로 표를 나열하고 WHERE에 연결 조건을 적는 이전식 내부 조인도 이 예시에서는 5행이지만, 결합 관계는 JOIN ... ON으로 분리하는 편이 더 명확해요. 외부 조인을 같은 방식으로 임의 치환하면 안 됩니다.

03

03. INNER·LEFT·RIGHT·FULL 중 무엇을 보존할까요?

INNER는 양쪽이 일치하는 조합만 반환합니다. LEFT는 왼쪽의 미일치 행을, RIGHT는 오른쪽의 미일치 행을, FULL은 양쪽의 미일치 행을 모두 보존합니다. 미일치 쪽의 열에 SQL NULL을 채워요.

같은 학생·학과 입력에서 실제 SQLite 비교(1:N의 매칭 학생 수 반영)
구문결과 행 수미일치 보존
INNER JOIN5행없음
LEFT JOIN6행학생 S105
RIGHT JOIN6행학과 D30
FULL OUTER JOIN7행학생 S105 + 학과 D30
↳ 결과 행 수와 보존을 구별

학생이 6명, 학과가 3개라는 사실만으로 결과가 6이나 3으로 결정되는 것은 아니에요. D10 소속 학생이 3명이므로 하나의 학과가 여러 결과 행에 반복됩니다. RIGHT JOIN은 이 예제에서 표의 위치를 뒤집은 LEFT JOIN으로도 표현할 수 있어요.

! SQLite 버전 경계

SQLite는 RIGHT/FULL OUTER JOIN을 3.39.0부터 지원합니다. 06R의 SQLite 3.38.4에서는 이번 문법 전체를 실행할 수 없습니다. 구형 환경에서는 무작정 동일 구문을 실행하지 마세요.

04

04. ON에 여러 조건을 넣을 수 있을까요?

ON은 행 쌍의 연결 여부를 정해요. ON s.department_id=d.department_id AND d.department_id='D10'은 학과 코드가 같고 D10일 때만 오른쪽을 연결합니다. LEFT JOIN이라면 연결되지 않은 왼쪽 학생은 제거하지 않고 NULL을 채워 보존해요.

↳ 복수 조건

두 열 이상으로 연결해야 하면 ON n.department_id=d.department_id AND n.campus_code=d.campus_code처럼 비교 조건을 함께 사용해요. 06S 전용 예제 C4에서는 둘 다 일치하는 N1·N3만 2행 남습니다.

! ON과 WHERE 혼동 금지

ON 조건은 논리적인 매칭 판정입니다. WHERE 조건은 결합 결과에서 행을 최종 선택합니다. 내부 조인과 외부 조인의 차이를 섞어 일반화하지 마세요.

05

05. 같은 이름의 열이면 USING으로 간단히

두 입력에 department_id라는 같은 이름의 열이 있을 때 JOIN ... USING (department_id)라고 적으면 이 열의 등호 조건을 지정합니다. ON s.department_id=d.department_id와 같은 일치 판단을 할 수 있지만 출력 형태는 달라요.

같은 INNER JOIN을 SELECT *로 표시한 SQLite 출력 구조
조인 구문출력 열 개수공통 department_id
USING (department_id)8열1번만 출력
ON s.department_id=d.department_id9열양쪽의 열이 각각 출력
↳ USING 표기법

USING의 괄호에는 열 이름만 적고 USING (s.department_id)처럼 테이블 별칭을 붙이지 않아요. 공통 출력 열은 department_id로 사용하면 DBMS 차이까지 비교하기 쉬워요.

↳ 출력 열 순서

D2의 8열과 D3의 9열 배치는 SQLite에서 확인한 SELECT * 결과예요. 출력 열 순서는 DBMS마다 다를 수 있어요. 열 순서가 중요하면 SELECT 목록에 필요한 열을 원하는 순서로 직접 적으세요.

! USING의 조건

USING을 모든 JOIN의 범용 축약형으로 생각하면 안 됩니다. 서로 다른 이름의 열이나 부등호·복잡한 조건은 ON을 쓰세요. 여러 공통 이름 중 일부만 선택할 수도 있습니다.

06

06. NATURAL JOIN은 왜 조심해야 할까요?

NATURAL JOIN은 두 표에서 이름이 같은 모든 열을 찾아 자동으로 등호 조건을 만듭니다. USING (department_id)처럼 한 열을 지정하는 것과 다릅니다. 다른 의미의 열까지 같은 이름이면 예상보다 적은 행이 나올 수 있어요.

06S 전용 NATURAL JOIN 비교 데이터(실제 SQL 입력)
학생 예제department_idcampus_code학과 예제에 같은 조합이 있는가?
N1D10A있음
N2D10B없음
N3D20B있음
N4D20A없음
↳ 자동 결합의 숨은 조건

NATURAL은 department_id와 campus_code를 둘 다 비교해 N1·N3 = 2행입니다. ON 또는 USING으로 department_id만 비교하면 N1~N4 = 4행입니다. 공통 열 이름 자체가 하나도 없다면 NATURAL INNER JOIN은 CROSS JOIN처럼 모든 조합을 만들 수 있어요.

! 스키마 변경 위험

공통 열을 새로 추가하거나 이름을 바꾸면 SQL을 수정하지 않아도 NATURAL JOIN의 조건이 달라질 수 있습니다. 학습과 유지보수에서는 의도한 열을 ON·USING으로 명시하는 편이 안전합니다. NATURAL에 별도의 ON/USING을 덧붙이지 않아요.

07

07. CROSS JOIN 구문은 어떤 뜻인가요?

CROSS JOIN에는 결합 키가 없고 왼쪽의 각 행을 오른쪽의 모든 행과 조합해요. 6명×3개 학과 = 18행입니다. INNER JOIN ... ON 1=1도 이 예제에서 같은 조합을 만들지만, 모든 조합이라는 뜻을 강조하려면 CROSS JOIN이 더 분명해요.

↳ 가능한 조합과 실제 소속은 다름

CROSS JOIN 뒤 WHERE로 D20만 선택하면 6행입니다. S105-D20이 생기더라도 실제로 S105가 D20 학과에 소속된다는 뜻이 아닙니다.

! 명시적 결합 권장

서로 다른 테이블과의 결합 조건을 빠뜨려 18행·42행처럼 불필요하게 많은 결과를 만드는 실수를 주의하세요. 여러 테이블의 콤마 조인과 명시 JOIN을 섞으면 DBMS별 우선순위 차이가 생길 수 있으니 피하세요.

08

08. 표 세 개를 잇는다면 JOIN은 몇 번 적나요?

학생(s)과 수강(e), 강좌(c)의 3개 테이블을 연결할 때는 s.student_id=e.student_id와 e.course_id=c.course_id의 조건을 각각 확인해야 해요. 한 테이블을 추가할 때 어떤 열을 연결할지 분명해야 합니다.

↳ LEFT 후 INNER의 함정

INNER+INNER의 결과는 수강 7행, LEFT+LEFT로 학생을 보존하면 S105의 NULL 한 행이 더해져 8행입니다. 그러나 첫 번째만 LEFT로 하고 뒤에 강좌를 INNER로 연결하면 S105가 다시 제외돼 7행이 됩니다.

! 논리적 결과와 실행계획

조인이 왼쪽에서 오른쪽으로 적혔다고 물리적 실행순서가 반드시 고정되는 것은 아니에요. 이 예제의 괄호 없는 연결 결과를 이해하는 논리적 해석과 DBMS의 실행계획은 구분합니다.

09

09. ON에 쓰면 6행, WHERE에 쓰면 3행?

LEFT JOIN의 ON에서 오른쪽 학과를 컴퓨터(D10)로 제한하면 연결할 오른쪽 행만 줄어들고 학생 6행은 그대로 남습니다. 반면 WHERE d.department_name='컴퓨터'로 필터링하면 NULL 학과를 포함한 나머지 학생이 제거되어 3행만 나옵니다.

LEFT JOIN 이후 조건 위치를 바꿨을 때
조건출력 행S105 포함?
ON에 학과 컴퓨터 조건6행예, 오른쪽 NULL
WHERE에 학과 컴퓨터 조건3행아니요
ON에 수강 C01 조건6행예, 오른쪽 NULL
WHERE에 수강 C01 조건4행아니요

H3은 ON에서 C01 수강만 연결해요. S103은 C02 수강 기록 E04가 있지만 C01 조건에 맞지 않아 오른쪽 열이 NULL이에요. S105는 원본 수강 기록이 없어 오른쪽 열이 NULL입니다. H5는 과목 조건 없이 전체 수강 기록을 연결한 뒤 WHERE e.enrollment_id IS NULL로 걸러요. S103은 E04가 연결되므로 빠지고, 실제 미수강 학생 S105만 남아요.

! 시험에서 중요한 함정

ON과 WHERE는 외부 조인에서 일반적으로 교환할 수 없습니다. WHERE에 오른쪽 열의 =, 비교·불일치 조건을 쓰면 NULL 보존 행이 사라질 수 있어요. 단, 모든 WHERE 조건이 반드시 보존 행을 지우는 것은 아니므로 조건의 실제 TRUE/FALSE/UNKNOWN을 확인하세요.

10

10. JOIN 문제를 풀 때 판단 순서

먼저 어떤 테이블이 보존 대상인지 찾고, 연결 조건에 들어가는 열 이름과 NULL을 확인한 뒤, 1:N으로 행이 증가하는지 계산하세요. 마지막으로 WHERE가 보존 행을 지우는지 확인하면 됩니다.

SQL 구문을 읽을 때 꼭 확인할 질문

LEFT / RIGHT / FULL보존되는 쪽모든 결과가 원본과 같은 행 수라는 오해

NATURAL공통 열 이름 전체department_id만 비교한다고 단정
LEFT JOIN ... ON ... WHEREON 매칭 다음 WHERE 필터WHERE가 항상 오른쪽 NULL을 보존한다고 단정

↳ 숫자 암기보다 규칙 이해

학습 문제에서 스키마·가상 데이터를 바꾸지 않는 한 A~H 시나리오의 결과는 재현할 수 있어요. 질문이 다른 데이터로 바뀌면 특정 행 수를 기계적으로 외우지 말고 매칭과 보존 규칙으로 다시 계산하세요.

11. SQL 32개를 복사해 결과를 비교해요

↳ 실행 환경과 예상 결과 구분

전체 스크립트는 새 빈 SQLite DB에 실습 데이터를 만들고, 이어지는 SELECT는 데이터를 읽어요. 결과표의 NULL은 실제 SQL NULL을 표시합니다. 제작 단계에서 Python SQLite 3.46.1, 통합 단계에서 3.50.4로 검증했으며 Oracle·PostgreSQL 실서버 실행은 미검증입니다.

12. 표준 조인 핵심 정리

  • JOIN만 쓰면 INNER, OUTER는 LEFT·RIGHT·FULL에 따라 보존하는 입력이 달라집니다.
  • ON은 조건을 자유롭게 적을 수 있고, USING은 양쪽에 존재하는 지정된 같은 이름 열을 등호로 비교합니다.
  • USING의 공통 출력 열은 하나이지만 ON의 SELECT *는 양쪽 열을 모두 출력합니다.
  • NATURAL JOIN은 양쪽의 이름 같은 열을 전부 조건으로 사용하여 스키마 변화에 민감합니다.
  • CROSS JOIN은 모든 쌍을 결합합니다.
  • 3개 이상 연결할 때는 각 JOIN의 ON과 INNER/LEFT 위치를 확인합니다.
  • 외부 조인 ON은 매칭을 판정하고 WHERE는 완성된 결과 행을 걸러 보존 행을 지울 수 있습니다.
↳ 한 문장으로 기억하기

JOIN 유형 → 연결 조건 → NULL 보존 → WHERE 필터 → 출력 열/행 수 순서로 보면 헷갈리는 결과도 설명할 수 있어요.
