WHERE 절WHERE Clause

개념부터 차근차근!

WHERE 절로 원하는 행만 찾아볼까요?

06M에서는 SELECT로 출력 열을 골랐고 06N에서는 함수로 값을 계산했어요. 이번에는 WHERE 조건을 사용해 학생 다섯 명 중 원하는 기록만 찾아봅니다. 조건이 TRUE인 행만 남는 이유를 실제 SQLite 결과로 연습해요.

WHERE는 원본 행을 삭제하지 않고 조회 대상 행을 필터링해요. 비교·BETWEEN·IN·LIKE와 NOT > AND > OR 우선순위, 괄호를 이해해야 합니다. NULL이 섞인 조건은 UNKNOWN이 될 수 있으므로 IS NULL과 NOT IN을 조심하세요. WHERE는 집계 전 행, HAVING은 집계 후 그룹을 조건으로 걸러요.

이 단원을 끝내면

  1. 1WHERE 절과 =, <>, >, >=, <, <= 비교 조건을 정확히 읽고 결과 행을 구해요.
  2. 2NOT·AND·OR의 논리적 우선순위를 설명하고 괄호로 조건을 명확하게 묶어요.
  3. 3BETWEEN의 양쪽 경계 포함, IN 값 목록, LIKE의 %·_와 ESCAPE를 구별해요.
  4. 4NOT IN 값 목록에 NULL이 섞이거나 비교 대상이 NULL일 때 UNKNOWN이 되는 원리를 이해해요.
  5. 5IS NULL·IS NOT NULL을 사용하고 WHERE는 TRUE인 행만 통과시킨다고 설명해요.
  6. 6동일한 조건도 괄호 유무에 따라 결과가 달라짐을 실제 SQL로 재현해요.
  7. 7WHERE의 행 필터링과 HAVING의 그룹 필터링을 비교하고 다음 GROUP BY 단원과 연결해요.
학습 기록을 불러오는 중이에요.

02

02. WHERE와 비교 연산은 어떻게 쓰나요?

기본형은 SELECT 열목록 FROM 테이블 WHERE 조건;이에요. =(같다), <>(다르다), >·>=·<·<=로 비교합니다. SQL에서 같다는 조건은 == 대신 `=`로 쓰는 것이 표준적인 방법이에요. `> 7`은 7을 제외, `<= 7`은 7을 포함합니다. 아래 도식에서 >, <, <= 결과까지 바꿔 보며 경계값을 확인하세요.

WHERE로 걸러진 행은 조회 결과에서만 빠집니다. 학생 테이블의 원본 행이 삭제되지는 않습니다. 원본에 행 5개가 있어도 반환 결과는 조건에 따라 0개일 수 있어요.

03

03. AND·OR·NOT 중 무엇이 먼저 적용되나요?

여러 조건을 함께 쓰면 논리 연산 우선순위를 이해해야 해요. 일반적인 조건식에서 `NOT` → `AND` → `OR` 순으로 결합됩니다. A OR B AND C는 A OR (B AND C)처럼 읽고, (A OR B) AND C는 다른 결과를 낼 수 있어요.

↳ SQL은 왼쪽부터 차례대로 행을 검사하지 않습니다

우선순위는 조건의 논리적 의미를 정하는 규칙이지 DBMS가 물리적으로 왼쪽 조건부터 차례대로 평가한다는 보장이 아닙니다. 최적화·단락 평가 등을 고려해 부작용이 있는 평가 순서를 가정하지 마세요.

04

04. BETWEEN·IN·LIKE로 범위와 패턴 찾기

`BETWEEN a AND b`는 a·b 양끝을 포함해요. IN (...)은 나열된 값 중 하나와 일치하는지 확인합니다. LIKE에서 `%`는 0개 이상의 문자, `_`는 정확히 한 문자를 뜻해요.

! 밑줄 문자와 LIKE 밑줄 와일드카드는 달라요

LIKE 'sql_%'는 실제 밑줄이 없는 sqlX5도 찾습니다. 밑줄 자체를 찾고 싶다면 SQLite에서는 LIKE 'sql!_%' ESCAPE '!'처럼 ESCAPE를 명시할 수 있어요. 백슬래시가 기본 ESCAPE라고 모든 DBMS에 일반화하지 마세요.

↳ LIKE와 문자 비교의 제품별 차이

SQLite 기본 LIKE는 ASCII 영문자에 한해 대소문자를 구분하지 않는 동작이 있으나, 비ASCII·Collation·설정은 DBMS마다 다릅니다. 이번 실습은 패턴 해석을 분명히 보여 주는 고정된 영문 코드만 사용합니다.

05

05. NOT IN에 NULL이 섞이면 왜 0행이 될까요?

x NOT IN (a,b)는 값 x가 목록의 모든 값과 다르다는 조건을 의미해요. 그런데 목록에 SQL NULL이 들어 있고 일치값을 찾지 못하면 결과가 TRUE가 아니라 UNKNOWN이 될 수 있어요. WHERE는 UNKNOWN을 반환 행으로 남기지 않습니다.

! NOT IN에 NULL이 있다고 언제나 모든 상황에서 UNKNOWN인 것은 아닙니다

예를 들어 D10 NOT IN ('D10',NULL)은 D10과 일치하는 값을 찾았으므로 FALSE입니다. D20 NOT IN ('D10',NULL)은 일치값이 없지만 NULL 때문에 UNKNOWN입니다. 이 데이터에서는 두 경우 모두 WHERE를 통과하지 않아 0행이 됩니다.

↳ NULL까지 포함해서 조회하려면?

조회 의도가 "D10이 아닌 학과 또는 미입력 학과"라면 department_id NOT IN ('D10') OR department_id IS NULL처럼 NULL을 명시적 조건으로 처리할 수 있어요. 서브쿼리의 NOT IN도 NULL 위험을 검토하세요. NOT EXISTS의 자세한 내용은 이후 서브쿼리 단원에서 학습합니다.

06

06. NULL은 어떻게 찾아야 할까요?

SQL NULL은 "값이 알려지지 않음/없음"을 의미해요. 그래서 department_id = NULL을 TRUE/FALSE 비교처럼 사용하면 안 됩니다. department_id IS NULL과 IS NOT NULL을 사용하세요. 비교 결과가 UNKNOWN인 행도 WHERE를 통과하지 못합니다.

↳ Z4 도식의 TRUE·FALSE·UNKNOWN은 SQL 출력 자료형이 아니에요

Z4의 세 단어는 CASE가 만든 설명용 문자열입니다. SQLite에서 비교식 department_id = 'D10' 자체를 SELECT로 확인하면 참은 숫자 1, 거짓은 0, NULL과의 비교는 SQL NULL로 표시됩니다. UNKNOWN이라는 문자열이 DBMS의 세 번째 논리 자료형으로 저장된다는 뜻은 아닙니다.

07

07. 복합 조건은 괄호로 명확하게 작성해요

조건이 길면 괄호로 의도한 평가 묶음을 표시하세요. D10 OR (9시간 이상 AND D20)과 (D10 OR 9시간 이상) AND D20은 서로 다르게 행을 필터링합니다. NOT (A OR B)의 결과는 NOT A AND NOT B와 논리적으로 같지만, NULL이 있을 때도 3값 논리를 함께 고려해야 해요.

↳ 가독성과 검증 가능성

괄호는 SQL 엔진보다 읽는 사람에게 특히 중요해요. 조건이 예상대로 작동하는지 실제 입력 행과 결과 행을 함께 비교하세요.

08

08. WHERE와 HAVING은 언제 사용하나요?

WHERE는 그룹을 만들기 전 개별 행을 필터링하고, HAVING은 집계 단계에서 그룹에 조건을 적용해요. 예를 들어 학습시간 7 이상 학생만 WHERE로 남긴 뒤 학과별 학생이 2명 이상인 그룹에 HAVING을 적용하면 D20만 남아요.

! WHERE에 집계 함수를 직접 쓰면 안 되는 일반적인 상황

그룹별 인원 COUNT(*) >= 2처럼 집계 결과에 대한 조건은 HAVING에 적습니다. WHERE COUNT(*) >= 2처럼 그룹 집계를 WHERE로 직접 필터링하면 오류가 납니다. 다음 06P 「GROUP BY, HAVING 절」에서 상세 구문과 예외를 다룹니다.

09

09. 새 SQLite 데이터베이스에서 직접 확인해요

새 빈 SQLite 3.x 데이터베이스에서 전체 SQL을 처음부터 실행해 보세요. 테이블 생성·학생 5행 삽입·비교·논리·패턴·NOT IN·NULL·WHERE/HAVING까지 재현할 수 있습니다. 아래 버튼을 바꾸면 전체 스크립트의 각 SELECT 문과 검증된 결과표를 비교할 수 있어요.

! 실제 SQL 실행 엔진이 아닙니다

브라우저 표는 사전에 SQLite로 실행해 검증한 학습용 시뮬레이션입니다. 온라인에서 실제 쿼리를 실행하지 않습니다. 같은 CREATE TABLE을 기존 DB에서 다시 실행하면 테이블 존재 오류가 날 수 있으므로 새 빈 DB에서 시작하세요.

10

10. WHERE 절 핵심만 정리해요

  • WHERE는 행을 필터링하며 원본 테이블을 지우지 않아요.
  • 비교 연산: =, <>, >, >=, <, <=. NULL 비교는 IS NULL로 확인하세요.
  • 우선순위: NOT > AND > OR. 의도가 복잡하면 괄호를 쓰세요.
  • BETWEEN은 두 경계를 포함하고 IN은 목록과의 일치를 검사해요.
  • LIKE의 %는 0개 이상 문자, _는 한 글자. 문자 자체로 검색하려면 ESCAPE를 사용해요.
  • NOT IN에 NULL이 있으면 UNKNOWN이 될 수 있어 결과가 예상과 달라져요. 일치한 값에 대해서는 FALSE일 수 있습니다.
  • WHERE는 TRUE만 남깁니다. FALSE와 UNKNOWN은 둘 다 제거돼요.
  • WHERE는 행, HAVING은 집계 단계에서 그룹의 조건을 검사합니다.
