그룹 함수Grouping Functions and Grouping Sets

개념부터 차근차근!

어디까지 합칠까요? ROLLUP·CUBE·그룹 함수

하나의 판매표로 지역별·품목별 합계와 총계를 만드는 방법을 배웁니다.

ROLLUP은 순서가 있는 소계, CUBE는 모든 집계 조합, GROUPING SETS는 선택한 조합이며 GROUPING은 실제 NULL과 소계를 구별한다.

이 단원을 끝내면

  1. 1일반 GROUP BY의 그룹과 소계·총계 수준을 구별한다.
  2. 2ROLLUP의 오른쪽부터 열을 제거하는 집계 수준을 쓸 수 있다.
  3. 3CUBE와 GROUPING SETS의 집계 수준과 행 수를 직접 계산한다.
  4. 4GROUPING과 GROUPING_ID/다중 인수 GROUPING의 마스크 값을 해석한다.
  5. 5실제 데이터 NULL과 소계용 NULL을 혼동하지 않는다.
  6. 6일반 GROUP BY 열 순서와 ROLLUP 인수 순서의 영향을 구분한다.
학습 기록을 불러오는 중이에요.
01

한눈에 보고 싶은 매출 보고서

가게 운영자가 다섯 건의 판매 기록을 받았습니다. “서울에서 책이 얼마 팔렸나요?”는 상세 묶음으로, “서울 전체 매출은?”은 지역 소계로, “전국에서 모두 얼마 팔렸나요?”는 전체 총계로 답합니다. 같은 원본 행을 서로 다른 기준으로 묶어 보여 주는 도구가 이번 단원의 그룹 함수입니다.

06V 전용 예시 — 실제 데이터, 판매 5건
판매ID지역 region품목 category금액 amount
1서울책100
2서울문구50
3부산책80
4부산문구20
5SQL NULL책30

모든 지역을 합친 금액은 100+50+80+20+30=280입니다. 마지막 행의 NULL은 “지역을 입력하지 않았다”는 원본 값입니다. 뒤에서 소계를 나타내려고 생기는 NULL과 구별합니다.

06P에서 이미 배운 SUM과 GROUP BY를 기초로 합니다. 06V에서는 그룹을 여러 종류로 만들어도 원본 판매를 중복 저장하지 않는다는 점에 집중하세요.

02

상세·소계·총계는 묶는 열이 달라요

일반 SQL GROUP BY region, category는 지역과 품목이 모두 같은 행을 한 그룹으로 묶습니다. 표의 (region, category)는 두 열이 남는 집계 수준을 뜻하며, (region)은 지역 소계, ()는 전체 총계를 뜻합니다. 확장 구문 GROUP BY ROLLUP(region, category)는 이 세 집계 수준을 한 번에 만듭니다.

같은 매출을 네 집계 수준에서 보기
집계 수준묶는 열그룹 개수결과 합계의 의미
상세(region, category)5각 지역·품목별 합계
지역 소계(region)3서울150 / 부산100 / 미입력30
품목 소계(category)2책210 / 문구70
총계()1전체280

표에서 “그룹 개수”는 원본에 어떤 값이 있는지에 따라 달라집니다. 두 열이 있다고 언제나 상세 5그룹인 것은 아닙니다.

서로 다른 집계 수준의 total을 모두 더하면 같은 매출이 반복 계산됩니다. 예를 들어 CUBE의 상세·지역·품목·총계 네 수준은 각각 280을 포함하므로 4×280은 새로운 매출이 아닙니다.

03

ROLLUP은 오른쪽부터 묶음을 없애요

ROLLUP(region, category)은 열 목록의 오른쪽인 category부터 제거하면서 세 가지 집계 수준을 만듭니다. (region, category) → (region) → () 순입니다. “지역 안의 품목”, “지역 전체”, “모든 지역 전체”를 한 보고서로 읽는 데 알맞습니다.

두 열 ROLLUP의 집계 수준
순서남는 GROUP BY 열행 수마스크 gid
1 상세(region, category)50
2 지역 소계(region)31
3 전체 총계()13

이 입력 데이터에서 전체 행 수는 5+3+1=9행입니다. 반면 ROLLUP(category, region)은 (category, region) → (category) → ()여서 상세 5+품목 소계 2+총계 1=8행입니다.

위 원형 SQL에서 GROUP BY ROLLUP으로 집계 수준을 지정합니다. SQLite에서 실행한 B4/B5는 각 수준을 GROUP BY로 구한 뒤 UNION ALL로 합칩니다.

ROLLUP 결과의 출력 순서까지 자동 보장되는 것은 아닙니다. 수업에서는 마스크와 ORDER BY를 넣어 순서를 고정했습니다.

04

CUBE는 가능한 모든 묶음을 만듭니다

CUBE(region, category)는 두 열을 각각 묶음에 포함할지 제외할지 선택하여 가능한 네 종류의 집계 수준을 모두 만듭니다. ROLLUP에는 없는 “품목만 묶은 소계”까지 볼 수 있습니다.

CUBE의 모든 집계 수준
GROUP BY 집계 수준행 수GROUPING(region)GROUPING(category)gid
(region, category)5000
(region)3011
(category)2102
()1113

이 예제에서는 CUBE 11행 = 상세 5 + 지역 소계 3 + 품목 소계 2 + 총계 1입니다. n개 독립 열의 집계 수준 종류는 2ⁿ개지만 실제 반환 행 수는 각 집계 수준에서 생기는 그룹 수의 합이므로 2ⁿ행이라고 단정하지 않습니다.

Oracle·PostgreSQL 실제 문법은 GROUP BY CUBE(region, category)입니다. C4는 SQLite에서 네 GROUP BY 결과를 UNION ALL로 결합한 대체 재현입니다.

CUBE의 합계 11행을 모두 다시 SUM하는 일은 전체 매출 계산이 아닙니다. 여러 집계 수준에서 같은 입력이 반복 요약됩니다.

05

GROUPING SETS는 필요한 묶음만 고릅니다

보고서에 상세 행은 필요하지 않고 지역별 합계, 품목별 합계, 전체 합계만 필요할 수도 있습니다. GROUPING SETS는 사용할 집계 수준을 괄호 안에 직접 나열합니다.

GROUP BY GROUPING SETS ((region), (category), ())는 지역 소계 3개 + 품목 소계 2개 + 총계 1개만 출력하므로 6행입니다. (region, category)가 목록에 없으므로 상세 5행은 나오지 않습니다.

같은 280을 다르게 보는 SQL 의미
구문묶음 종류이번 예제 반환 행 수
ROLLUP(region, category)상세, 지역, 총계9
CUBE(region, category)상세, 지역, 품목, 총계11
GROUPING SETS ((region),(category),())지역, 품목, 총계6

빈 괄호 ()는 “아무 열도 그룹으로 남기지 않는 총계 수준”입니다. 단순히 “출력하지 않는다”는 뜻이 아닙니다.

GROUPING SETS는 여러 수준의 결과를 UNION ALL 방식으로 합친 것과 대응합니다. 그룹 수준을 중복해서 명시한 경우 결과 행 중복 가능성도 있으므로 자동으로 DISTINCT 처리된다고 가정하지 마세요.

06

GROUPING(열)은 집계 수준에 포함되면 0, 제외되면 1

소계에서는 그 수준에서 묶지 않은 열을 NULL로 표시합니다. GROUPING(region)은 “현재 행이 region을 그룹 기준으로 사용했는가?”를 알려 줍니다. 열을 사용했으면 값이 실제 NULL이어도 0이고, 집계 수준에서 열을 제외했으면 1입니다.

GROUPING 플래그를 숫자가 아닌 뜻으로 읽기
GROUPING(region)의미region이 NULL일 수도 있나요?
0현재 집계 수준에 region 포함예: 입력 지역이 원래 NULL
1현재 집계 수준에서 region 제외예: 모든 지역의 책 합계

GROUPING(category)도 같은 원리입니다. 여기에서 0/1은 해당 값이 NULL인지 여부를 검사한 결과가 아닙니다. SQL의 IS NULL과 GROUPING은 질문 자체가 다릅니다.

Oracle·PostgreSQL 양쪽 모두 단일 열 GROUPING(열)의 0/1 의미를 제공하지만 이 패키지는 서버 실행이 아니라 공식 문서에 근거했습니다.

07

두 개의 GROUPING 값을 하나의 숫자로

Oracle의 GROUPING_ID(region, category)는 각 GROUPING 플래그를 왼쪽에서 오른쪽으로 이어 붙여 이진수로 해석합니다. 오른쪽 인수 category가 1의 자리이고 왼쪽 인수 region이 2의 자리여서 gid=2×GROUPING(region)+GROUPING(category)입니다.

gid(region,category) 읽기
집계 수준region 플래그category 플래그이진수십진수 gid
상세00000
지역 소계01011
품목 소계10102
전체 총계11113

PostgreSQL에는 Oracle의 GROUPING_ID 이름 대신 여러 인수의 GROUPING(region, category)가 동일한 비트 마스크 역할을 합니다. PostgreSQL의 GROUPING(region)은 단일 플래그이고 GROUPING(region, category)는 마스크입니다.

GROUPING_ID(category, region)처럼 인수 순서를 바꾸면 비트 위치도 바뀝니다. 품목 제외 지역 소계는 원래 gid=1이지만 역순 인수일 때 2입니다.

마스크 숫자는 행 정렬이나 전체 합계의 크기를 뜻하지 않습니다. “어떤 그룹 열이 빠졌는가”의 부호입니다.

08

겉으로 같은 NULL도 서로 다른 이유

sale_id=5의 region=NULL은 입력 데이터 자체의 지역 미기록입니다. 이 행을 region과 category로 상세 집계하면 (NULL, 책, 30)이면서 GROUPING(region)=0입니다. 반면 모든 지역에서 책을 합치면 (NULL, 책, 210)이지만 GROUPING(region)=1입니다.

눈에 보이는 region=NULL 두 행의 차이
regioncategorytotalg_region정확한 의미
NULL책300원본의 지역 미입력 그룹
NULL책2101모든 지역의 책 소계

실제 (region=NULL) 그룹의 “품목 전체” 30과 모든 데이터의 총계 280은 둘 다 화면에서 (NULL, NULL)처럼 보일 수 있습니다. 30행은 (g_region,g_category)=(0,1), 280행은 (1,1)입니다.

잘못된 표시: COALESCE(region, '모든 지역')은 실제 지역 미입력까지 “모든 지역”으로 바꾸므로 오해를 만듭니다. 안전한 표시: CASE WHEN GROUPING(region)=1 THEN '모든 지역' WHEN region IS NULL THEN '지역 미입력' ELSE region END.

GROUPING()을 사용할 수 없는 SQLite 재현에서는 g_region/g_category를 각 GROUP BY 묶음에 맞춰 명시적으로 기록합니다. 실제 NULL 판정만으로 이 플래그를 만들어서는 안 됩니다.

09

괄호 안 열 순서가 중요한 때가 있어요

일반 GROUP BY region, category와 GROUP BY category, region은 같은 입력에서 동일한 묶음을 계산합니다. 열이 어떤 순서로 적혔는지는 그룹의 구성에 영향을 주지 않지만, SELECT 열의 배치와 결과 출력 정렬은 다른 문제입니다.

ROLLUP은 순서가 중요합니다. ROLLUP(region, category)는 지역 소계를 남기고 ROLLUP(category, region)은 품목 소계를 남기므로 같은 데이터라도 9행 대 8행이 됩니다.

이번 데이터의 그룹 비교
방식소계 종류전체 행 수
GROUP BY region,category상세 그룹만5
GROUP BY category,region상세 그룹만5
ROLLUP(region,category)지역 소계 포함9
ROLLUP(category,region)품목 소계 포함8

Oracle GROUPING_ID의 인수 순서도 숫자를 바꿉니다. 비트열은 함수에 전달한 인수 순서에서 정의되며 GROUP BY 열의 출력 표시 순서와 별개입니다.

ORDER BY 없이 “ROLLUP 결과에서 소계가 항상 마지막에 나온다”라고 설명하지 마세요. 학습 도식의 순서와 실제 DBMS 정렬 보장은 별개입니다.

10

시험 문장을 집계 수준으로 번역해 보세요

집합 연산자에서 “어떤 행을 합치는가?”를 물었다면, 그룹 함수에서는 “어떤 열을 남겨서 묶는가?”를 먼저 파악하세요. 정답을 서둘러 고르지 말고 원하는 집계 수준을 괄호로 적으면 실수를 줄일 수 있습니다.

요구사항 → 적절한 GROUP BY 구문
보고서 요구선택할 구문이유
상세+지역별 소계+총계ROLLUP(region,category)오른쪽 category부터 제거
상세+지역별+품목별+총계CUBE(region,category)모든 부분집합 수준
지역별+품목별+총계만GROUPING SETS ((region),(category),())상세 수준 제외
일반 지역·품목별만GROUP BY region,category한 수준만 계산

정확한 행 수는 각 그룹 수준에서 나온 결과 행 수를 더해 구합니다. 같은 판매가 서로 다른 수준에서 요약되므로 수준 간 집계 결과까지 더해 총매출로 삼으면 안 됩니다.

자체 학습용 예상 변형 문제이며 실제 기출문항·빈도 통계가 아닙니다.

11

40개의 쿼리로 결과를 직접 확인합니다

A1~H5의 40개 사례는 같은 sales 표로 실행했습니다. 사례마다 SQLite SQL, 결과 열과 행, 해설을 확인할 수 있습니다. 원본 SQL은 06V_SQLITE_GROUP_FUNCTIONS.sql입니다.

WHERE는 그룹화 전에 입력 행을 거릅니다(H1). HAVING은 그룹화 후 조건에 맞는 결과 그룹을 남깁니다. H2의 HAVING SUM(amount) >= 100은 일반 GROUP BY region의 합계에 적용합니다. 아래 원형 SQL의 HAVING GROUPING(...)은 ROLLUP이 만든 상세·소계·총계 중에서 플래그 조합이 맞는 수준을 남깁니다.

Oracle/PostgreSQL의 ROLLUP/CUBE/GROUPING SETS/GROUPING 구문은 06V_DBMS_DIALECT_NOTES.md에 별도 제공합니다. SQLite 검증 결과를 이 네이티브 구문의 서버 실행 성공으로 표기하지 않습니다.

B4=9행, B5=8행, C4=11행, D4=6행, F5=30과 280 두 행, H1=6행·총계 230, H4=COUNT 0/SUM NULL을 먼저 살펴보세요.

정렬을 지정한 SQL의 행 순서만 고정 기대값과 비교합니다. 강의용 표의 시각적 묶음은 실제 엔진의 기본 반환 순서를 주장하지 않습니다.

12

핵심은 “남기는 그룹 열”입니다

  • ROLLUP(a,b) = (a,b), (a), ()로 오른쪽 열부터 제거합니다.
  • CUBE(a,b) = (a,b), (a), (b), ()로 두 열의 모든 부분집합을 계산합니다.
  • GROUPING SETS는 필요한 그룹 수준만 직접 골라 나열합니다.
  • GROUPING(열)=0은 현재 집계 수준에서 그 열을 묶는다는 의미, 1은 열이 집계에서 제외됐다는 의미입니다.
  • Oracle GROUPING_ID(a,b)와 PostgreSQL GROUPING(a,b)는 오른쪽 인수가 최하위 비트인 마스크 0~3을 만듭니다.
  • 실제 입력 NULL과 소계용 NULL은 GROUPING 플래그로 구별합니다.
  • 일반 GROUP BY 열 순서가 달라도 같은 그룹이지만 ROLLUP 인수 순서와 그룹 마스크의 인수 순서는 의미가 있습니다.

이번 5행 예제에서 합계 280, ROLLUP(region,category) 9행, CUBE 11행, 지정한 GROUPING SETS 6행입니다. 숫자는 예시 데이터에 종속됩니다.
