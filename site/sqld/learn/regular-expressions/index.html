정규 표현식Regular Expressions

개념부터 차근차근!

문자열 속 규칙을 찾을까요? 정규 표현식

앞서 PIVOT으로 데이터의 모양을 바꾸었다면, 이번에는 저장된 글자의 모양을 살펴볼 거예요. 학생 코드와 연락처 문자열 속에서 일정한 규칙을 찾는 방법을 단계별로 배웁니다.

정규식은 문자 종류·반복·위치·그룹을 조합한 검색 패턴입니다. 포함 검색과 전체 형식 검사를 구별하고, 매치 여부/추출/치환/위치/횟수의 반환값을 혼동하지 마세요. SQL NULL과 DBMS별 함수 차이도 중요합니다.

이 단원을 끝내면

  1. 1정규식 패턴 검색의 필요성과 LIKE·GLOB의 차이를 설명한다.
  2. 2문자 클래스·범위·특수문자 이스케이프의 의미를 예제에 적용한다.
  3. 3반복 수량자 *, +, ?, {n,m}의 포함 결과를 구분한다.
  4. 4앵커 ^/$와 괄호·선택 연산자의 범위에 따라 결과를 판단한다.
  5. 5REGEXP_LIKE, REGEXP_SUBSTR, REGEXP_REPLACE, REGEXP_INSTR, REGEXP_COUNT의 목적과 반환형을 구분한다.
  6. 6부분 매치·NULL·대소문자·잘못된 형식 통과 문제를 분석한다.
  7. 7SQLite 교육용 UDF와 Oracle·PostgreSQL 실제 문법이 다름을 설명한다.
학습 기록을 불러오는 중이에요.
01

01. 학생 코드에서 원하는 규칙을 어떻게 찾을까요?

학생 신청서를 저장한 표에는 S101-AB12처럼 학생 번호 + 과목 코드가 있어요. “AB가 들어 있는 코드”는 단순한 포함 검색으로 찾지만, “번호 3자리-영문 2자리-숫자 2자리”처럼 문자 종류와 반복 횟수까지 검사하려면 정규 표현식이 편리합니다.

실습 코드 일부 — 학습용 가상 데이터
IDraw_text관찰할 점
C01S101-AB12정상적인 예시 형식
C02S102-CD007숫자 3개
C05S105-AB숫자 0개
C07S107-A.B문자 그대로의 점(.)
C09S109-AB12 extra뒤에 추가 문자열
C14SQL NULL값이 없음
↳ 핵심 질문

AB라는 글자가 있는지를 찾는 일과, AB 뒤에 숫자가 1개 이상이고 문자열 끝까지 이어지는지 검사하는 일은 다릅니다.

! 실습 DBMS 조건

SQLite는 정규식을 기본 제공하지 않습니다. 06AA의 실습 SQL rx_* 함수와 REGEXP 연산은 첨부 Python 검증기에서 등록한 교육용 사용자 정의 함수로 실행합니다. Oracle의 함수와 동일한 구현이라고 취급하지 않습니다.

02

02. LIKE와 정규식은 어떤 점이 다를까요?

LIKE는 %(0글자 이상), _(정확히 1글자)의 단순 와일드카드를 씁니다. 정규식은 [0-9](숫자 한 글자), {3}(정확히 3번), ^(처음), $(끝)처럼 문자 규칙을 조합할 수 있어요.

같아 보이는 기호라도 규칙이 달라요
표현LIKE정규식
%길이 제한 없는 임의 문자열일반 문자 %
_임의 1글자일반 문자 _
*일반 문자 *직전 요소를 0회 이상 반복
?일반 문자 ?직전 요소를 0~1회 반복
.일반 문자 .문자 하나(보통 줄바꿈 제외)
↳ A1·A3·H2로 확인

LIKE '%AB%'는 부분 포함, rx_like(raw_text,'^S10[0-9]-')는 형식 접두부 검색입니다. LIKE의 %와 정규식의 %는 같은 기호가 아닙니다.

! SQLite GLOB 혼동

SQLite GLOB의 *·?는 정규식의 *·?와 동작이 다릅니다. 예제 A2는 비교용입니다.

03

03. [A-Z]와 [0-9]로 문자 종류를 고르고, 점을 찾으려면?

[A-Z]는 대문자 영문 하나, [0-9]는 숫자 하나, [ABC]는 세 글자 중 하나입니다. [ ^ ]처럼 떨어뜨려 쓰는 게 아니라 [^0-9]라고 쓰면 숫자가 아닌 문자 하나를 뜻해요.

문자 클래스·리터럴 사용
패턴뜻보기
[0-9]0~9 중 한 글자7
[A-Z]{2}대문자 영문 두 글자AB
[^0-9]숫자가 아닌 문자 한 글자A
\.점(.) 문자 자체A.B
\+더하기(+) 문자 자체A+B
↳ B1 결과

^S[0-9]{3}-[A-Z]{2}[0-9]{2}$는 C01과 C12 두 코드에 맞아요. C02는 마지막 숫자가 3개이므로 제외됩니다.

! 역슬래시 경계

정규식 패턴의 \.은 “아무 한 글자”인 .과 다릅니다. 언어별 문자열 리터럴의 역슬래시 처리 방식도 별개이므로 DBMS의 실제 입력 구문을 확인해야 합니다. 학습 예제는 SQLite + Python UDF 기준입니다.

04

04. 별표(*), 더하기(+), 물음표(?)의 차이

반복 수량자는 바로 앞의 문자 또는 문자 클래스에 붙습니다. AB[0-9]*는 AB 다음 숫자 0개 이상, AB[0-9]+는 1개 이상, AB[0-9]?는 0개 또는 1개예요. {n,m}은 n~m번 반복합니다.

실제 데이터에서의 끝 패턴 차이
패턴(부분)결과 건수포함되는 코드
-AB[0-9]*$5행C01, C05, C06, C10, C11
-AB[0-9]+$4행C01, C06, C10, C11
-AB[0-9]?$1행C05
-AB[0-9]{2,3}$3행C01, C06, C11
↳ C1과 C2 차이

C05 S105-AB는 숫자가 0개이므로 *에는 맞지만 +에는 맞지 않아요.

! 수량자는 조건 전체가 아니에요

{2,3}만 붙여서는 문자열 전체의 형태가 지정되지 않습니다. 다른 위치의 문자·처음/끝 앵커까지 함께 확인하세요.

05

05. 처음과 끝(^,$), 그룹과 선택(|)을 이해해요

^는 시작 위치, $는 끝 위치입니다. 둘을 함께 쓰면 “문자열 전체가 이 규칙에 맞는지” 검사하기 쉽습니다. (1|2)는 1 또는 2 중 하나를 선택한다는 뜻입니다.

앵커로 바뀌는 결과
패턴C09: S109-AB12 extraC01: S101-AB12
AB12일치일치
AB12$불일치일치
^S101-AB12$불일치일치
↳ D3 결과

^S10(1|2)-는 C01, C02 두 건입니다. 괄호가 선택 범위를 결정합니다.

! 선택 연산자의 범위

^S101|AB12$는 (^S101)|(AB12$)와 같이 해석될 수 있지만 ^(S101|AB12)$는 전체 문자열이 S101 또는 AB12인 경우만 일치합니다. 괄호가 없으면 의도와 달라져요.

06

06. REGEXP_LIKE: 해당 패턴이 들어 있나요?

Oracle의 REGEXP_LIKE(source, pattern[, match_param])는 조건식으로 사용하여 대상 문자열이 패턴에 맞는지 판정합니다. PostgreSQL은 ~·~* 연산자와 regexp_like() 함수 등으로 정규식 검색을 지원해요. 06AA의 실행 가능한 SQL에서는 별도 rx_like() 등록 함수를 사용합니다.

간이 연락처 패턴 예제
예제결과
E1: 영문/숫자/점/밑줄/더하기 + @ + 도메인 + .2글자 이상7행
E2: @example.com$ (대소문자 구분)3행 — 잘못된 bad@@example.com도 포함
E3: i 옵션으로 대소문자 무시4행
↳ 정확한 의미

정규식 함수는 문자열 일부분이 맞아도 성공하는 경우가 많습니다. 입력값 전체의 모양을 검사하고 싶을 땐 처음과 끝 앵커를 조합하세요.

! 이메일 검증이 아닙니다

예제의 단순 이메일 패턴은 정규식 이해용입니다. 실제 RFC 이메일 검증이나 도메인 존재 확인을 보장하지 않습니다. @example.com$만으로는 bad@@example.com도 통과합니다.

07

07. REGEXP_SUBSTR: 일치하는 글자만 꺼내요

검색이 되는지 확인하는 것과, 일치하는 문자열 자체를 꺼내는 것은 다릅니다. Oracle REGEXP_SUBSTR는 발생 순서·캡처 그룹을 선택할 수 있고, SQLite 예제 rx_substr는 첫 일치 또는 지정한 발생 순서만 구현한 교육용 함수예요.

실습 F2·F3·F4
예제결과
rx_substr('X12 Y345','[0-9]+',2)345
rx_substr('ABC','[0-9]+')SQL NULL
rx_group('S101-AB12',pattern,1)AB
rx_group('S101-AB12',pattern,2)12
↳ 실습 범위

rx_group은 Python re 캡처 결과를 보여 주는 교육 전용 도우미입니다. Oracle의 함수 이름·인자와 동일하다고 복사하면 안 됩니다.

! NULL의 원인

추출 결과가 NULL일 때는 일치 항목이 없어서일 수도 있고 입력값 자체가 NULL일 수도 있습니다. 원본 값을 함께 확인하세요.

08

08. 바꾸고(REPLACE), 위치 찾고(INSTR), 개수 세기(COUNT)

REGEXP_REPLACE는 패턴에 일치하는 구간을 다른 문자열로 바꿉니다. REGEXP_INSTR는 일치 시작/끝 위치를, REGEXP_COUNT는 매치 횟수를 다룹니다. 각각 반환 자료가 문자열·위치 숫자·개수 숫자로 달라요.

실제 실행 결과 G1~G5
예제출력
rx_replace('S101-AB12','[0-9]','#')S###-AB##
rx_replace('S101-AB12','[0-9]+','{NUM}')S{NUM}-AB{NUM}
rx_instr('S101-AB12','AB')6
rx_instr('ABC','[0-9]+')0
rx_count('AB12-CD345','[0-9]+')2
↳ 위치는 1부터

S101-AB12에서 A는 6번째 문자입니다. 찾지 못하면 위치는 0이고, rx_substr로 같은 패턴을 찾지 못하면 NULL입니다.

! 치환 문자열 호환성

SQLite 교육 UDF rx_replace는 문자열을 그대로 치환하며 백레퍼런스 치환 기능을 지원하지 않습니다. Oracle REGEXP_REPLACE의 백레퍼런스·발생 순번 의미와 동일하다고 가정하지 마세요.

09

09. NULL·대소문자·부분 일치가 만드는 함정

문자열이 있으나 매치되지 않으면 이 실습의 rx_like는 0, 매치되면 1, 입력이 SQL NULL이면 NULL입니다. WHERE는 TRUE인 행만 남기므로 NULL 판정은 별도로 처리해야 해요.

실습 결과
조건결과
rx_like('AbC','^abc$')0
rx_like('AbC','^abc$','i')1
rx_like(NULL,'abc')SQL NULL
rx_instr('ABC','[0-9]+')0
rx_substr('ABC','[0-9]+')SQL NULL
↳ H1 전체 집계

study_codes는 총 16행, ^S[0-9]{3}- 접두부 일치 15행, 원본 NULL 1행입니다.

! Oracle의 기본 대소문자 처리

Oracle의 기본 정규식 비교는 collation 등의 영향을 받을 수 있으므로 “기본은 언제나 대소문자 구분”이라고 일반화하지 마세요. 비교 조건을 명확히 할 때 match_param을 검토합니다.

10

10. SQLite·Oracle·PostgreSQL 문법을 혼동하지 마세요

정규 표현식은 여러 DBMS에서 지원하지만 함수 이름·일치 여부 반환·플래그·패턴 규칙·SQL 리터럴 이스케이프·버전이 모두 같지는 않습니다. 연습용 SQLite UDF는 Oracle과 PostgreSQL 문법을 전부 복제하지 않아요.

표준 문법이 아니라 벤더별 기능을 구분
의도Oracle 19cPostgreSQL 18SQLite 기본
패턴이 존재하는가REGEXP_LIKE(col, 'pat')col ~ 'pat' 또는 regexp_like(col,'pat')기본 내장 없음; UDF 등록
첫 일치 구간REGEXP_SUBSTR(col,'pat')regexp_substr(col,'pat')기본 내장 없음
치환REGEXP_REPLACE(col,'pat','x')regexp_replace(col,'pat','x','g') (*g는 전체 치환)기본 내장 없음
발생 위치REGEXP_INSTR(col,'pat')regexp_instr(col,'pat')기본 내장 없음
↳ 규칙

원형 SQL은 각각 06AA_ORACLE19C_EXAMPLES.sql, 06AA_POSTGRESQL18_EXAMPLES.sql을 참고하세요. 원형 SQL은 실제 해당 DB 서버에서 실행하지 않았습니다.

! 원형과 대응 SQL 분리

rx_like/rx_substr/rx_replace/rx_instr/rx_count/rx_group은 학습자가 이해하도록 만든 별도 UDF입니다. SQL Server는 내장 정규식 지원 여부가 버전별로 달라서 이 문서에서 특정 버전의 원형 정규식 함수를 동일하다고 단정하지 않습니다.

12. 정규 표현식 핵심 정리

  • LIKE %/_와 정규식 */?의 뜻이 다릅니다.
  • [0-9], [A-Z], [^...]로 한 글자의 종류를 지정하고 \.로 점을 문자 그대로 찾습니다.
  • * 0회 이상, + 1회 이상, ? 0~1회, {n,m} n~m회입니다.
  • ^와 $는 처음과 끝, (...)와 |는 그룹과 선택입니다.
  • REGEXP_LIKE=판정, SUBSTR=일치 부분, REPLACE=치환, INSTR=위치, COUNT=횟수입니다.
  • SQL NULL과 미매치를 구분하고, Oracle/PostgreSQL 원형 문법과 SQLite 교육 UDF를 구별하세요.
↳ 기억법(비공식)
