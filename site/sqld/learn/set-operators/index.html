집합 연산자Set Operators

개념부터 차근차근!

두 명단을 합치면 몇 행일까요? 집합 연산자

앞 단원에서는 서브쿼리로 다른 SELECT의 결과를 활용했어요. 이제 두 SELECT의 결과를 합치거나 공통 행과 차집합을 찾겠습니다.

집합 연산은 SELECT 결과를 행 단위로 비교해요. UNION은 중복 제거, UNION ALL은 보존, INTERSECT는 공통 행, EXCEPT/MINUS는 왼쪽−오른쪽입니다. 열 수·타입·위치를 맞추고 NULL·ORDER BY·DBMS별 혼합 우선순위를 확인하세요.

이 단원을 끝내면

  1. 1집합 연산에 필요한 열 개수·순서·타입 조건을 설명해요.
  2. 2UNION과 UNION ALL의 중복 결과 행 수를 계산해요.
  3. 3INTERSECT가 반환하는 공통 학생과 두 열짜리 행을 찾아요.
  4. 4EXCEPT/MINUS의 방향을 바꾸면 결과가 달라지는 이유를 설명해요.
  5. 5집합 중복 판정에서 NULL의 의미와 일반 등호 비교를 구별해요.
  6. 6두 열짜리 행의 동등 비교가 모든 출력 위치를 기준으로 한다는 점을 이해해요.
  7. 7최종 ORDER BY와 첫 SELECT의 열 이름 규칙을 설명해요.
  8. 8여러 집합 연산자의 SQLite/PostgreSQL 우선순위 차이와 괄호의 필요성을 설명해요.
학습 기록을 불러오는 중이에요.
01

01. 두 결과표를 합치거나 비교할 수 있을까요?

06T에서는 안쪽 SELECT 결과를 바깥 쿼리의 조건으로 사용했어요. 이번에는 두 개의 SELECT가 반환한 행의 목록 자체를 합치거나 비교합니다. 예를 들어 “컴퓨터 학과 학생”과 “SQL 입문 수강 학생”의 명단을 합쳐 보겠습니다.

왼쪽 A: 컴퓨터 학과(D10) 학생 3행
student_id
S101
S103
S106
오른쪽 B: SQL 입문(C01) 수강 학생 4행
student_id
S101
S102
S104
S106

A={S101,S103,S106}, B={S101,S102,S104,S106}. 두 SELECT에 S101과 S106이 공통이에요. UNION·UNION ALL·INTERSECT·EXCEPT가 이 두 목록을 어떻게 다루는지 실제 행으로 확인하겠습니다.

↳ 집합 연산은 JOIN과 달라요

JOIN은 테이블의 열을 가로로 연결하는 경우가 많고, 집합 연산은 SELECT 결과의 행을 세로로 이어 붙이거나 행 집합을 비교합니다. 다만 결과의 열 개수·대응 위치·자료형 호환을 반드시 확인해야 해요.

! 행 순서에 대한 주의

집합 결과를 반환할 때는 ORDER BY가 없는 행 순서를 보장하지 않아요. 이번에 나열하는 명단은 비교를 돕기 위해 마지막 ORDER BY로 정렬한 결과예요.

02

02. 합치려면 열 개수·순서·타입부터 맞춰요

집합 연산을 하는 두 SELECT는 같은 개수의 열을 반환해야 합니다. 데이터는 열 이름이 아니라 위치(1번째 열끼리, 2번째 열끼리)로 대응합니다. 대응 열의 자료형도 호환되어야 해요.

세 가지 확인 항목
확인올바른 예주의
열 개수왼쪽 2열 ↔ 오른쪽 2열1열 ↔ 2열은 오류
열 위치(학생 ID, 학과 코드) ↔ (학생 ID, 학과 코드)(학과 코드, 학생 ID)라면 의미가 달라짐
열 타입문자 ↔ 문자, 숫자 ↔ 숫자Oracle은 문자형과 숫자형 그룹을 자동으로 섞지 않음
↳ A1·A3·A5를 비교해요

A1은 양쪽 별칭이 달라도 한 열의 학생 ID가 합쳐지고, A3는 두 열의 위치로 결합해요. A5는 CAST(... AS TEXT)로 자료형을 명시해 의도를 분명히 했습니다.

↳ SQLite에서 숫자 1과 문자열 '1' 비교

SELECT 1 AS v UNION SELECT '1' AS v ORDER BY v; 결과는 2행이에요. 첫 행은 정수 1, 둘째 행은 문자열 '1'입니다. SQLite는 집합의 중복 판정에서 두 값을 서로 다른 자료형으로 비교해요.

↳ SQLite에서 CAST로 자료형을 맞춘 결과

SELECT 1 AS v UNION SELECT CAST('1' AS INTEGER) AS v ORDER BY v; 결과는 정수 1 한 행이에요. CAST로 오른쪽 값을 정수로 바꾸면 두 값이 같아져 UNION이 중복 한 행을 제거합니다.

! SQLite의 느슨한 타입 규칙을 SQL 공통 규칙으로 외우지 마세요

SQLite 실습에서는 값의 자료형을 유지해 비교해요. Oracle 19c 공식 문서에 따르면 집합 연산에서 대응 열은 같은 자료형 그룹이어야 하고, 숫자형과 문자형 그룹을 섞으면 오류가 발생합니다. PostgreSQL에도 별도의 타입 호환 규칙이 있어요.

↳ 자가 확인 1 · UNION 양쪽이 1열과 2열이면 왜 오류일까요?

정답 · 두 SELECT의 열 개수가 같아야 해요. 집합 연산은 같은 위치의 열끼리 대응시켜 행을 비교하는데, 여기서는 두 번째 열의 짝이 없어서 오류가 발생합니다.

03

03. UNION과 UNION ALL은 중복 처리만 달라요

UNION은 두 SELECT의 결과를 합친 뒤 완전히 같은 출력 행을 한 번만 남깁니다. UNION ALL은 중복 제거 없이 양쪽 행을 모두 반환합니다. 현재 A는 3행, B는 4행이고 공통 학생 ID는 두 개입니다.

A와 B를 합친 결과
연산자출력 학생 ID행 수
UNIONS101 · S102 · S103 · S104 · S1065행
UNION ALLS101×2 · S102 · S103 · S104 · S106×27행
↳ 중복 판단 단위는 전체 출력 행

B5에서는 같은 S101이라도 (S101,C01)과 (S101,C02)는 다른 두 열짜리 행입니다. UNION이 학생 ID만 보고 중복을 없애지는 않아요.

! UNION ALL이 언제나 왼쪽 행부터 나오지는 않아요

중복은 남지만 정렬 보장과는 무관합니다. 결과 순서는 최종 ORDER BY를 사용해야 합니다. B2의 순서는 정렬을 명시한 결과입니다.

04

04. 양쪽에 모두 있는 행은 INTERSECT

INTERSECT는 두 SELECT 결과에 모두 있는 출력 행을 반환합니다. A(D10)에도 B(C01)에도 있는 학생만 고르면 S101과 S106입니다.

공통 학생 찾기
비교공통 학생결과
D10 ∩ C01S101, S1062행
D10 ∩ C02S101, S1032행
C01 ∩ C02S1011행
↳ JOIN 또는 EXISTS와 무엇이 다를까요?

이 예제에서 JOIN이나 EXISTS로 같은 학생을 찾을 수도 있습니다. 그러나 INTERSECT는 완성된 두 SELECT의 같은 위치 행 전체를 비교하고 일반형은 중복을 제거한다는 점이 핵심입니다.

! INTERSECT ALL을 기본 의미로 가르치지 않아요

이번의 INTERSECT는 중복을 제거하는 일반형입니다. 일부 DBMS에 존재하는 INTERSECT ALL은 중복 처리 규칙이 달라 별도 문법·버전 확인이 필요합니다.

05

05. 왼쪽에서 오른쪽을 빼는 EXCEPT·MINUS

차집합은 왼쪽 SELECT에 있으나 오른쪽 SELECT에는 없는 행을 남깁니다. SQLite·PostgreSQL에서는 EXCEPT, Oracle 19c에서는 MINUS로 표현합니다. 방향을 바꾸면 결과도 달라집니다.

차집합 방향이 바뀌면
연산남는 학생행 수
B(C01) − A(D10)S102, S1042행
A(D10) − B(C01)S1031행
↳ SQLD에서 자주 보는 MINUS

Oracle 19c의 MINUS와 SQLite의 EXCEPT는 여기서 다루는 중복 제거 차집합에 대응합니다. Oracle AI Database 26ai 문서에는 EXCEPT도 나오지만, Oracle 버전에 따라 문법 지원을 확인해야 해요.

! SQLite에서 MINUS를 그대로 실행하지 마세요

이번 40개 SQL은 SQLite용 EXCEPT로 실행·검증했습니다. MINUS는 Oracle 문서의 비교 구문이며 Oracle 실서버 실행 결과를 검증했다고 주장하지 않습니다.

06

집합 연산에서 중복을 제거할 때 같은 위치의 SQL NULL끼리는 같은 것으로 취급합니다. 일반 비교식 NULL = NULL의 결과는 UNKNOWN이며, SQLite는 이를 SQL NULL로 반환해요. 06T에서 본 NOT IN의 UNKNOWN과 같은 진리값이에요.

! 결과표의 NULL 표시는 실제 NULL이에요

위 실습 표에서 SQL NULL 표시는 데이터베이스의 실제 NULL을 나타냅니다. 문자열 'NULL'은 글자 네 개로 이루어진 별도 값이에요.

↳ SQL NULL과 문자열 'NULL' 비교

SELECT NULL AS tag UNION SELECT 'NULL' AS tag ORDER BY tag;를 SQLite에서 실행하면 2행이 나옵니다. 첫 행은 실제 SQL NULL, 둘째 행은 문자열 'NULL'이에요. 두 값이 서로 달라 UNION 결과에 각각 남습니다.

07

07. 두 열이면 한 행 전체로 비교해요

SELECT가 두 열을 반환하면 (첫 열, 둘째 열) 한 쌍을 통째로 비교합니다. 같은 학과 코드가 있어도 점수가 다르면 다른 행입니다. NULL이 포함된 두 열짜리 행도 집합 중복 판정 규칙에 따라 비교됩니다.

두 열 집합 연산에서의 예
연산행 수설명
F1: UNION6행서로 다른 (dept,mark) 조합만
F2: UNION ALL11행6행 + 5행 모두 유지
F3: INTERSECT3행(NULL,NULL)·(NULL,80)·(D10,90)
F4: EXCEPT2행(D20,80)·(D30,NULL)
↳ F5의 다른 별칭도 위치로 판단

왼쪽은 left_dept,left_score, 오른쪽은 right_dept,right_score라고 이름을 붙여도 1열↔1열, 2열↔2열로 비교합니다. 출력 열 이름은 첫 SELECT를 따릅니다.

! 열을 잘못 바꿔 끼우면 틀린 의미가 됩니다

같은 개수의 열을 출력하는 것으로 충분하지 않아요. 각 위치의 열 의미·타입이 대응하는지도 직접 확인해야 합니다.

08

08. ORDER BY는 전체 집합 결과에 적용해요

집합 연산에서 ORDER BY는 완성된 결과 전체의 순서를 정합니다. SQLite의 복합 SELECT에서는 ORDER BY를 전체 문의 마지막에 두며, 이 실습에서는 첫 번째 SELECT의 출력 별칭 또는 출력 열 위치를 사용합니다.

↳ 최종 별칭과 계산식 정렬

G3의 첫 SELECT는 dept, 두 번째는 other_alias이지만 최종 열 이름은 dept예요. G4처럼 별도 계산식으로 정렬하려면 복합 SELECT를 인라인 뷰로 감싸 바깥 ORDER BY를 사용할 수 있습니다.

! 중간 SELECT마다 ORDER BY를 넣지 마세요

이번 SQLite 복합 SELECT에서는 각 단순 SELECT 내부에 ORDER BY를 무작정 끼워 넣을 수 없습니다. 개별 SELECT의 정렬·행 제한이 필요하면 DBMS에 맞는 하위 쿼리 구조를 사용하고, 최종 결과의 정렬은 바깥에 별도로 명시하세요.

↳ 자가 확인 2 · UNION 전체 결과를 정렬하려면 ORDER BY는 어디에 쓸까요?

정답 · 마지막 SELECT 뒤, 세미콜론 앞에 한 번 써요. 그 위치의 ORDER BY는 UNION으로 합친 결과 전체에 적용됩니다.

09

09. 집합 연산자를 섞을 때 우선순위가 같을까요?

이번 비교에서는 A=D10 학생, B=C01 수강자, C=C02 수강자예요. 같은 A UNION B INTERSECT C라도 DBMS의 결합 규칙에 따라 다른 행이 나올 수 있습니다. 괄호로 의도한 집합을 확정하는 것이 안전합니다.

A∪B와 B∩C를 다르게 묶는 경우
묶음결과 학생행 수
(A UNION B) INTERSECT CS101, S1032행
A UNION (B INTERSECT C)S101, S103, S1063행
↳ SQLite와 PostgreSQL, Oracle 문서 비교

SQLite는 여러 집합 연산자를 왼쪽부터 결합해 H1을 2행으로 평가합니다. PostgreSQL 문서의 우선순위를 적용하면 INTERSECT부터 묶여 같은 입력에서 3행이 예상됩니다. Oracle 19c·26ai 문서는 현재 같은 우선순위와 왼쪽부터 결합을 명시하지만, 향후 변경 가능성을 안내해 괄호 권장입니다.

! H2·H3은 SQLite에서 의도적으로 괄호를 구현한 재현 코드

SQLite에서는 단순 SELECT 둘을 문법상 바로 괄호로 감싸지 않고 FROM (SELECT ... UNION SELECT ...) x처럼 인라인 뷰를 사용해 묶음을 보입니다. PostgreSQL·Oracle 서버 실행은 이번 패키지의 검증 범위가 아닙니다.

10. 시험에서 먼저 확인할 다섯 가지

긴 집합 SQL을 보면 ① 두 SELECT의 열 개수 ② 대응 열의 타입과 위치 ③ 중복 제거 여부 ④ NULL ⑤ 마지막 정렬·우선순위 순으로 해석하세요. SQL 구문의 숫자를 외우기보다 출력 행이 왜 생기고 지워지는지를 직접 추적하는 것이 중요합니다.

실수하기 쉬운 문장
오개념정확한 판단
UNION은 단순히 3행+4행=7행UNION은 동일 행을 제거하므로 현재 예제 5행
INTERSECT는 원본 전체 행 중 같은 ID만 비교SELECT가 반환한 모든 열이 같아야 같은 출력 행
A EXCEPT B와 B EXCEPT A는 같다차집합은 방향에 따라 달라짐
NULL은 어떤 집합 연산에도 들어갈 수 없다중복·교집합·차집합의 집합 판정에서는 NULL끼리 같은 것으로 취급
ORDER BY는 양쪽 SELECT가 각각 적용전체 복합 SELECT 뒤의 ORDER BY가 최종 결과 정렬

12. 집합 연산자를 한눈에 정리해요

  • UNION은 행 전체가 같은 중복을 제거하고, UNION ALL은 그대로 유지합니다.
  • INTERSECT는 두 SELECT 결과 모두에 있는 출력 행만 남깁니다.
  • EXCEPT(SQLite·PostgreSQL)·MINUS(Oracle 19c)는 왼쪽−오른쪽의 차집합입니다.
  • 두 SELECT는 열 개수와 대응 위치/타입을 맞춰야 합니다.
  • 중복 제거를 하는 집합 연산에서는 SQL NULL끼리를 같은 것으로 취급합니다. 이는 NULL = NULL이 TRUE라는 뜻이 아닙니다.
  • 집합 연산의 ORDER BY는 전체 결과를 정렬하며, 표준적인 출력 이름은 첫 SELECT에서 옵니다.
  • 집합 연산자 혼합 시 SQLite와 PostgreSQL의 우선순위가 다르므로 괄호/인라인 뷰로 의도를 명확히 하세요.
↳ 핵심 흐름

열·타입 확인 → 중복 처리 → 집합 방향 → NULL → ORDER BY·묶음 순서로 판단하세요.
