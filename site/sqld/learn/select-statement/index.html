SELECT 문SELECT Statement

개념부터 차근차근!

SELECT로 원하는 행과 열을 골라 볼까요?

학생 3명이 있는 테이블에서 이름만 확인하거나 D10 학과 학생만 찾으려면 어떻게 할까요? 실제 SQLite의 SELECT 문으로 하나씩 확인해요.

FROM은 읽을 데이터의 출처를 정하고, WHERE는 행을 걸러낸 뒤 SELECT 열 목록으로 출력값을 정해요. DISTINCT는 선택한 전체 결과 행의 중복을 제거하고, AS 별칭과 계산식은 출력 열을 바꾸지만 원본 테이블을 수정하지 않아요. 결과 순서는 ORDER BY가 없으면 보장되지 않아요.

이 단원을 끝내면

  1. 1SELECT 열 목록과 FROM 테이블의 기본 형태를 직접 읽고 작성해요.
  2. 2SELECT *와 필요한 열만 지정한 조회의 결과 열 수를 비교해요.
  3. 3열 별칭 AS와 공백이 있는 별칭의 큰따옴표 사용을 설명해요.
  4. 4DISTINCT·ALL이 하나 또는 여러 출력 열의 중복에 주는 영향을 구별해요.
  5. 5산술·문자열 표현식을 결과 열로 만들고 NULL 및 DBMS 방언에 주의해요.
  6. 6FROM → WHERE → SELECT → DISTINCT의 논리적 처리 흐름과 결과 행·열을 해석해요.
학습 기록을 불러오는 중이에요.
01

01. 필요한 정보만 읽어도 될까요?

06L에서 테이블은 행(기록)과 열(속성)의 모음이라고 배웠어요. 학생 이름만 필요할 때 학생ID·학과·학습 시간까지 전부 가져와야 할까요? SELECT는 조회할 값을, FROM은 읽을 테이블을 지정합니다.

06L에서 이어지는 학생 3명에 06M 전용 연습값 study_hours를 추가했어요
student_idstudent_namedepartment_idstudy_hours
S101민지D105
S102준호D207
S103민지D108
↳ 데이터 연속성과 이번 단원의 추가값

S101·S102·S103의 ID·이름·학과는 06H~06L과 동일합니다. study_hours(5, 7, 8)는 06M에서 계산 연습을 위해 새로 만든 가상 값이며 이전 단원의 데이터와 원본 학습 기록을 변경하지 않습니다.

02

02. SELECT와 FROM, 무엇을 읽고 어디서 가져오나요?

가장 기본적인 형태는 SELECT 열이름 FROM 테이블이름; 입니다. 앞의 SELECT에는 출력할 열이나 계산식을 쓰고, FROM에는 데이터를 읽을 테이블을 적어요. 세미콜론(;)은 SQL 문장의 끝을 나타내며 실행 환경에 따라 입력 방식이 달라질 수 있어요.

SELECT student_id, student_name FROM study_students ORDER BY student_id
student_idstudent_name
S101민지
S102준호
S103민지
! SELECT만으로 원본이 바뀌지 않아요

SELECT는 데이터를 조회하는 문장입니다. INSERT·UPDATE·DELETE처럼 테이블의 행을 변경하지 않아요. 이 단원에서는 결과 비교를 위해 ORDER BY student_id를 붙였습니다.

03

03. SELECT *와 일부 열만 선택하는 방법

별표(는 기본적으로 해당 테이블의 출력 가능한 열 전체를 펼쳐요. SELECT student_id, student_name**처럼 쉼표로 열을 나열하면 필요한 열만 보여 줍니다. 어느 쪽이든 WHERE가 없다면 이 예제의 학생 기록은 3행이에요.

이번 예제의 열 개수 비교
SQL 선택결과 행결과 열
SELECT *3행4열
SELECT student_id, student_name3행2열
SELECT student_name3행1열
! 별표 사용의 실무적 주의

SELECT *는 연습에 편리하지만, 테이블에 열이 추가되면 결과의 열 구성도 달라질 수 있어요. 필요한 열을 명시하면 결과를 더 쉽게 이해하고 관리할 수 있습니다.

04

04. 열 별칭 AS와 따옴표는 어떤 역할인가요?

AS는 조회 결과에서 보이는 열 제목에 임시 이름을 붙여요. 예를 들어 student_name AS name은 화면의 열 이름을 name으로 바꾸지만 저장된 테이블의 열 이름은 유지됩니다. AS는 생략 가능한 경우도 있습니다.

열 별칭의 작성 예시(SQLite 3.x 실행 확인)
SQL 일부출력 열 제목
student_name AS namename
student_name namename
student_name AS "학생 이름"학생 이름
! 큰따옴표와 작은따옴표를 섞지 마세요

큰따옴표("...")는 표준 SQL에서 공백 있는 식별자·별칭 등을 감쌀 때 사용합니다. 작은따옴표('...')는 일반적으로 문자열 값에 사용해요. SQLite는 일부 비표준 따옴표 표기를 허용하지만 다른 DBMS에서 동일하게 동작한다고 가정하면 안 됩니다.

05

05. DISTINCT와 ALL은 왜 다른가요?

SQL의 SELECT는 기본적으로 중복 결과 행을 허용해요. SELECT ALL은 그 동작을 명시한 것이고, SELECT DISTINCT는 선택한 출력 열의 조합이 전부 같은 행을 하나로 줄입니다.

원본 학과 D10·D20·D10의 중복 처리
조회결과
SELECT department_idD10, D10, D20 (3행)
SELECT DISTINCT department_idD10, D20 (2행)
SELECT DISTINCT department_id, study_hours(D10,5), (D10,8), (D20,7) (3행)
! DISTINCT는 특정 열 하나에만 적용되지 않아요

SELECT DISTINCT department_id, study_hours는 두 열을 합친 행 전체의 중복을 비교합니다. D10이 같아도 학습 시간 5와 8이 다르므로 둘 다 남아요. 출력 순서는 ORDER BY를 적었을 때만 보장됩니다.

06

06. SELECT에서 계산하거나 문자열을 합칠 수 있나요?

SELECT 열 목록에는 기존 열 외에 **산술식(+)·곱셈(*)·문자열 연결 등의 표현식을 쓸 수 있어요. 가상 학습 시간에 2를 곱한 값을 조회할 수 있지만 테이블의 study_hours 값 자체는 바뀌지 않습니다.**

SQLite 3.x의 계산과 연결 결과
학생study_hours * 2student_name || '-' || student_id
S10110민지-S101
S10214준호-S102
S10316민지-S103
↳ DBMS 차이와 NULL

SQLite·PostgreSQL·Oracle에서는 보통 ||가 문자열 연결 연산자이지만 SQL Server 등은 연산자·함수가 다를 수 있어요. SQL의 숫자 연산에서 값이 NULL이면 결과도 일반적으로 NULL입니다. 이번 SQL의 실제 계산 결과는 SQLite로 확인합니다.

07

07. SQL을 적는 순서와 처리 순서가 다를까요?

SQL은 SELECT를 먼저 적지만, 단순 조회를 이해할 때는 FROM(대상) → WHERE(조건에 맞는 행) → SELECT(결과 열 계산) → DISTINCT(중복 제거) 순서로 생각하면 편해요. ORDER BY는 마지막 결과의 순서를 정합니다. 이 흐름은 논리적 설명이며 실제 DBMS의 물리 실행 계획이 항상 같다는 뜻은 아니에요.

D10 학생만 남기고 이름을 선택한 결과
쿼리행열
SELECT student_name FROM study_students WHERE department_id = 'D10'2행: 민지, 민지1열
SELECT DISTINCT student_name FROM study_students WHERE department_id = 'D10'1행: 민지1열
! WHERE에서 SELECT 별칭을 쓰는 것에 주의

표준 SQL의 일반적인 이름 해석에서 SELECT 결과 별칭은 WHERE의 조건 이름으로 사용하지 않습니다. SQLite는 일부 별칭을 WHERE에서 허용하는 확장이 있어요. DBMS 간에 동일하게 작동하도록 조건에는 원본 열 이름이나 표현식을 사용하세요.

08

08. 결과의 행과 열 수를 어떻게 해석하나요?

SELECT 열 목록은 결과의 열 구성을, FROM·WHERE는 후보 행과 필터링을 결정해요. DISTINCT로 중복을 줄이면 행 개수가 다시 바뀔 수 있어요. 별칭은 출력 열 이름을, ORDER BY는 결과 순서를 바꿉니다.

같은 테이블에서 다른 모양이 되는 결과
조건결과 행결과 열
SELECT *34
SELECT student_id, student_name WHERE D1022
SELECT DISTINCT student_name WHERE D1011
! 정렬이 없는 결과에 번호를 붙이지 않아요

학생 S101이 항상 첫 행에 나온다고 외우지 마세요. 순서가 필요한 결과에는 ORDER BY를 작성합니다. 반면 표에 데이터가 3행 있다는 사실과 ORDER BY에 의해 그 행들이 정렬되는 것은 서로 다른 개념입니다.

09

09. 처음부터 SQL로 조회를 재현해 봐요

이 코드는 새 빈 SQLite 3.x 데이터베이스에서 그대로 실행할 수 있습니다. 테이블 생성 → 3행 삽입 → 기본 조회 → 별칭 → 중복 제거 → 계산 → WHERE 조회까지 한 번에 실험하고, 아래 결과표를 직접 비교하세요. 브라우저의 표는 실제 실행 엔진이 아닌 검증된 예상 결과 시뮬레이션입니다.

↳ 독립 실행 주의

같은 이름의 study_students 테이블이 이미 존재하는 DB에서 CREATE TABLE을 재실행하면 오류가 날 수 있습니다. 기존 프로젝트 데이터베이스는 변경하지 않고, 새 SQLite DB 또는 별도 인메모리 DB를 사용해요.

  • 06L은 테이블·무결성의 큰 지도였고, 06M은 한 테이블에서 원하는 결과를 만드는 연습입니다.
  • JOIN과 여러 테이블의 복잡한 조건은 별도 단원에서 학습합니다.
  • NULL·집계·ORDER BY 상세 문법도 뒤 단원에서 심화합니다.
10

10. SELECT의 핵심을 한 번에 정리해요

  • SELECT 열 목록 FROM 테이블: 무엇을 볼지와 어디에서 볼지 정해요.
  • SELECT * / 일부 열**: 결과 열 구성이 달라져
  • AS 별칭: 조회 결과의 열 제목을 임시로 바꿔요. 공백이 있는 별칭은 큰따옴표로 감싸요.
  • DISTINCT / ALL: 출력 열 조합의 중복을 줄이거나 그대로 유지해요.
  • 산술식·문자열 연결: 조회 결과에 새 계산 열을 만들지만 저장된 값은 바뀌지 않아요.
  • FROM → WHERE → SELECT → DISTINCT → ORDER BY는 단순 조회를 이해하는 논리적 흐름이며, 실제 실행 순서의 절대 규칙이 아니에요.
  • 결과 행 수와 열 수, 정렬을 따로 생각하세요. ORDER BY 없이는 반환 순서를 보장할 수 없어요.
