Null 속성의 이해Understanding NULL Attributes

개념부터 차근차근!

NULL과 0은 왜 다를까요?

점수가 0점인 신청과 점수가 아직 없는 신청은 다르게 처리해야 해요. NULL은 조회와 계산 결과에 어떤 차이를 만들까요?

NULL은 값이 없거나 알려지지 않음을 나타내며 0과 다릅니다. NULL이 포함된 일반 비교는 UNKNOWN이고, WHERE는 TRUE인 행만 선택해요. IS NULL 검사, NULL 제외 집계와 LEFT JOIN의 미매칭 NULL을 구분해야 합니다.

이 단원을 끝내면

  1. 1NULL과 숫자 0·빈 문자열·공백, 미입력 상태를 구별하고 DBMS별 예외를 말할 수 있어요.
  2. 2NULL 허용/NOT NULL 및 DEFAULT를 업무 속성과 연결해서 설명해요.
  3. 3일반 NULL 비교·3값 논리·WHERE에서의 UNKNOWN을 예측해요.
  4. 4IS NULL·IS NOT NULL로 올바른 결과 행을 찾고 NULL이 포함된 산술·문자 연결의 결과를 설명해요.
  5. 5COUNT(*)·COUNT(열)·SUM/AVG의 NULL 처리와 LEFT JOIN에서 만들어진 NULL을 구별해요.
학습 기록을 불러오는 중이에요.
01

01. 값이 없는 것과 0인 것은 같을까요?

예를 들어 신청자 A01의 추가점수는 0점이고, A03의 추가점수는 아직 기록되지 않았어요(NULL). 0점은 측정된 값이지만 NULL은 저장된 값이 없다는 표시예요. 둘을 같다고 처리하면 실제 데이터의 의미가 달라져요.

독립적인 신청 설문 예제(applications)
신청ID추가점수(score)메모(memo)
A010빈 문자열 ''
A02100NULL
A03NULL공백 한 칸 ' '
A0450상담
↳ 예제 데이터 약속

신청 A01~A04는 NULL을 비교하려고 만든 별도 가상 설문 데이터예요. 이전 학생 S101~S103과 수강신청 E501~E503을 변경하거나 추가하는 것이 아니에요. 표에서 NULL은 SQL NULL의 읽기용 표시이고, 문자 'NULL'이 아니에요.

! 중요한 구별

미입력은 입력하지 않았다는 업무 상황이고, 실제 저장값은 컬럼의 기본값(DEFAULT), NOT NULL, 애플리케이션 규칙에 따라 달라져요. 미입력=반드시 NULL은 아니에요.

02

02. NULL·0·빈 문자열·공백은 어떻게 다를까요?

NULL은 값이 존재하지 않거나 알려지지 않았다는 표시이고, 숫자 0은 실제 숫자, 빈 문자열 ''은 길이 0의 문자 데이터, 공백 ' '은 공백 한 글자예요. 이 차이를 실제 저장·비교에서 확인해요.

SQLite에서 확인하는 값의 구별
표기예시 데이터SQLite에서 IS NULL의미
NULLA02 메모참값이 없음
0A01 점수거짓숫자 0
''A01 메모거짓길이 0인 문자열
' 'A03 메모거짓공백 한 글자
↳ DBMS 차이

Oracle Database는 현재 빈 문자열을 NULL로 취급해요. 위 표와 도식의 빈 문자열 비교는 SQLite 기준이며, Oracle에 그대로 적용하면 안 돼요. 이 장의 SQL 실행 파일은 SQLite 방언으로 고정했어요.

! NULL의 표시

SQL NULL과 문자열 'NULL'은 달라요. 화면에 NULL 글자가 보이더라도 실제 DB 값이 NULL인지 텍스트인지 확인해야 해요.

03

03. 어떤 속성에 NULL을 허용할까요?

필수 속성은 값을 반드시 저장해야 하므로 NOT NULL, 선택 속성은 업무상 값이 없을 수 있어 NULL 허용을 고려해요. 신청ID처럼 행을 식별하는 속성은 빠져서는 안 돼요. SQL의 필수 여부는 실제 컬럼 제약으로 확인해요.

가상 신청 테이블의 속성 설계
속성제약예시업무 의미
application_idPK + NOT NULLA01신청을 구별
scoreNULL 허용A03은 NULL아직 점수 기록 전
memoNULL 허용A02는 NULL메모 작성이 선택
categoryNULL 허용A04는 NULL분류가 미확정일 수 있음
↳ DEFAULT와 미입력

score INTEGER DEFAULT 0처럼 기본값이 선언돼 있고 INSERT에서 열을 생략하면 0이 들어갈 수 있어요. 반면 score INTEGER에 기본값이 없으면 보통 NULL이 저장돼요. 미입력 상태만 보고 저장값을 단정하면 안 돼요.

! ERD 주의

논리 모델의 선택 속성 표기와 물리 DB의 NULL 허용 여부는 연결되지만 동일한 그림 기호만으로 모든 DB 제약을 확정할 수 없어요. 사용자 교재의 IE/Barker 예시도 표기 규칙을 구분해서 읽어야 해요.

04

04. NULL과 비교하면 왜 UNKNOWN이 나올까요?

SQL의 일반 비교 =·<>·>에서 한쪽이 NULL이면 참도 거짓도 판단할 수 없어 UNKNOWN이 돼요. NULL = NULL도 참이 아니라 UNKNOWN이에요. 논리 연산 AND·OR·NOT은 TRUE/FALSE/UNKNOWN 세 상태로 판단해요.

SQL 3값 논리의 대표 규칙
식판정
NULL = NULLUNKNOWN
NULL <> 3UNKNOWN
NOT UNKNOWNUNKNOWN
FALSE AND UNKNOWNFALSE
TRUE OR UNKNOWNTRUE

WHERE는 TRUE인 행만 남겨요. FALSE와 UNKNOWN인 행은 조회 결과에서 제외돼요. 추가점수 score > 0 조건에서 A01의 0점은 FALSE, A03의 NULL은 UNKNOWN이므로 둘 다 빠지고 A02·A04만 남아요.

! UNKNOWN과 FALSE는 다름

둘 다 WHERE 결과에서는 빠지지만, 3값 논리에서 서로 다른 상태예요. FALSE AND UNKNOWN은 FALSE이고, TRUE OR UNKNOWN은 TRUE인 점을 함께 기억해요.

05

05. NULL인지 확인하려면 어떤 조건을 쓰나요?

NULL을 찾으려면 score = NULL이 아니라 score IS NULL을 사용해요. 값이 존재하는 행을 고르려면 score IS NOT NULL이에요. 일반 비교 = NULL은 모든 행에서 UNKNOWN이 되어 WHERE가 통과시키지 않아요.

신청 점수 조건별 결과
WHERE 조건나오는 신청ID행 수
score = NULL(없음)0
score IS NULLA031
score IS NOT NULLA01, A02, A043
score > 0A02, A042
↳ 올바른 필터

SELECT application_id FROM applications WHERE score IS NULL ORDER BY application_id;는 A03만 반환해요. 모든 일반 비교가 NULL을 감지하지 못하므로 NULL 여부는 명시적으로 검사해요.

! SQL 방언 주의

SQLite의 IS 연산자는 NULL 비교뿐 아니라 다른 동작도 지원해요. 이 단원에서는 여러 DBMS에 공통인 IS NULL / IS NOT NULL 문법을 권장해요.

06

06. NULL을 계산하거나 문자와 붙이면?

score + 5는 점수가 NULL이면 결과도 NULL이에요. SQLite에서 문자열 연결 연산자 ||도 어느 한쪽이 NULL이면 결과가 NULL이에요. 단, 문자 연결의 함수/NULL 처리 방식은 DBMS에 따라 다를 수 있어요.

SQLite 연산 예제
식A01(score=0)A03(score=NULL)
score + 55NULL
'점수:' || score점수:0NULL
COALESCE(score, 0)00
↳ 원본 값은 그대로

COALESCE(score, 0)은 NULL을 표시하거나 계산할 때 임시로 0으로 대체하는 표현식이에요. 원래 표의 A03.score가 실제 0으로 수정되는 것은 아니에요.

! DBMS별 함수와 연결 방식

Oracle의 NVL과 SQL Server의 ISNULL 같은 함수명은 DBMS별 차이가 있어요. COALESCE를 기본 설명에 사용하고, SQLite의 || 결과를 모든 DBMS의 연결 함수 결과로 일반화하지 않아요.

07

07. COUNT와 AVG는 NULL을 어떻게 다룰까요?

집계에서 COUNT(*)는 행 전체 개수, COUNT(score)는 점수가 NULL이 아닌 행 개수예요. SUM(score)와 AVG(score)도 NULL을 제외한 값으로 계산해요. 0은 NULL이 아니므로 계산에 포함돼요.

A01~A04 점수: 0, 100, NULL, 50
집계 식결과근거
COUNT(*)4전체 네 행
COUNT(score)30, 100, 50의 세 행
SUM(score)1500 + 100 + 50
AVG(score)50.0150 ÷ 3
AVG(COALESCE(score,0))37.5150 ÷ 4
↳ 모두 NULL인 경우

점수가 모두 NULL인 집계 그룹에서 COUNT(score)는 0이지만 SQLite SUM(score)와 AVG(score)는 NULL이에요. NULL을 0으로 간주하는 것이 아니라 계산 대상에서 제외한다는 의미예요.

! 나누는 개수

SUM(score) / COUNT(*)는 NULL이 있는 경우 보통 AVG(score)와 같지 않아요. 점수를 실제 입력한 사람만 평균 내는지, 미입력을 0으로 취급할지 업무 목적에 따라 결정해야 해요.

08

08. LEFT JOIN에서 나타난 NULL은 어디서 왔을까요?

06H에서 쓴 학생 S101·S102·S103, 수강신청 E501~E503 데이터를 그대로 재사용해요. 학생 기준 LEFT JOIN에서는 미신청 학생 S103을 보존하고, 매칭된 신청이 없으므로 오른쪽 테이블의 열을 NULL로 확장해요.

학생 기준 JOIN의 결과
학생신청ID (오른쪽)INNER/LEFT
S101E501둘 다 표시
S101E502둘 다 표시
S102E503둘 다 표시
S103NULLLEFT만 표시
↳ 출처 구분

S103의 student_id는 NULL이 아니라 S103이에요. NULL은 SQL LEFT JOIN이 조회 결과의 미매칭 신청 열에 채워 넣은 값이지, 원본 학생 정보가 누락되었다는 뜻이 아니에요.

! WHERE와 ON

WHERE e.course_id='C02'는 미매칭 행의 NULL이 UNKNOWN이라 S103을 제외해요. 이는 06H에서 다룬 외부 JOIN의 ON/WHERE 차이와 같은 원리예요.

09

09. 원본 표부터 결과 행까지 추적해 봐요

신청 설문 A01~A04에서 점수가 없는 사람을 찾고, 점수가 있는 사람의 평균을 구한 뒤, 학생 LEFT JOIN의 NULL과 비교해요. NULL은 저장값 부재를 나타내거나 OUTER JOIN의 결과에서 만들어질 수 있다는 점을 구분하세요.

! 시험 문제 읽는 순서

NULL인지(IS NULL), 일반 비교인지(=·<>), WHERE에서 TRUE가 되는지, 집계에 실제로 참여하는 행이 몇 개인지를 순서대로 확인해요.

10

10. NULL의 핵심 규칙 요약

  • NULL은 0이나 빈 문자열·공백 문자와 같지 않아요(Oracle의 빈 문자열 처리는 예외).
  • 속성의 NULL 허용 여부는 업무 규칙과 DB 제약으로 정하고, 미입력만 보고 NULL이라고 단정하지 않아요.
  • 일반적인 NULL 비교는 UNKNOWN, WHERE는 TRUE만 반환해요.
  • NULL 여부는 IS NULL / IS NOT NULL로 검사해요.
  • NULL이 포함된 산술 연산은 NULL, SQLite의 || 문자 연결도 NULL이에요. 다른 DBMS의 연결 함수는 따로 확인해요.
  • COUNT(*)는 전체 행, COUNT(열)과 AVG(열)은 NULL을 제외해요. 숫자 0은 포함해요.
  • LEFT JOIN의 NULL은 매칭 실패한 오른쪽 열의 결과일 수 있어요.
↳ 관련 단원

06H 「관계와 조인의 이해」의 LEFT JOIN·ON/WHERE 차이를 복습해요. 이후 SQL 기본 및 활용 과목에서 NULL 표현식과 집계를 다시 다룰 수 있어요.
